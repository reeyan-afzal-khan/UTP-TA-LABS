\chapter{Contiguous Memory Allocation}\label{ch:allocation}
\chapterguide{Know that a process needs memory for code, data, heap, and stack.}{Explain fixed/variable partition allocation, internal and external fragmentation, and trace first-fit, best-fit, and worst-fit policies.}

\section{The allocation problem}
A memory manager must map process memory demands onto available physical memory. Early and simplified schemes assign each process one contiguous region. The policy decides which free block or \term{hole} should satisfy a request.

\section{Fragmentation}
\term{Internal fragmentation} is unused space \emph{inside} an allocated region because the allocated unit is larger than the request. \term{External fragmentation} is free memory split across separated holes so that sufficient total free memory may exist without one large enough contiguous hole.

\section{First fit}
\term{First fit} scans holes from the beginning and chooses the first one large enough. It is fast because the search can stop early.

\section{Best fit}
\term{Best fit} chooses the smallest hole that is still large enough. It minimizes the leftover size for the current request, but repeated use may create many tiny unusable holes.

\section{Worst fit}
\term{Worst fit} chooses the largest available hole, attempting to leave a reasonably large remainder. This does not guarantee lower fragmentation overall.

\section{Worked comparison}
For blocks 100, 500, 200, 300, 600 and requests 212, 417, 112, 426, the three policies choose different placements. To solve such questions consistently:
\begin{enumerate}
  \item mark every block initially free;
  \item process requests in the given order;
  \item among currently free blocks, apply exactly one policy rule;
  \item compute fragment = block size $-$ request size;
  \item mark the chosen block unavailable in the simplified one-file-per-block lab model.
\end{enumerate}

\begin{pitfall}
The supplied lab programs model each block as usable by only one file/process. That is a useful partition-allocation simulation, but it is not the same as a full variable-size heap allocator that splits and coalesces holes after every request.
\end{pitfall}

\begin{chapterrecap}
\begin{itemize}
  \item Contiguous allocation assigns each request one continuous region.
  \item Internal fragmentation wastes space inside an allocation; external fragmentation scatters free space between allocations.
  \item First, best, and worst fit differ only in the hole-selection policy, but that choice changes future memory state.
\end{itemize}
\end{chapterrecap}
