\section{Records inside files}
Applications often impose a record structure on a byte stream. The Lab 10 programs store student or employee records and then display/search them. Two broad encodings appear:
\begin{itemize}
  \item \textbf{text format}: fields are converted to characters with functions such as \texttt{fprintf()} and parsed with \texttt{fscanf()};
  \item \textbf{binary format}: an in-memory structure is written as raw bytes with \texttt{fwrite()} and read with \texttt{fread()}.
\end{itemize}

\section{Sequential search}
A simple search rewinds the file and scans one record at a time until a key matches. Cost is $O(n)$ records in the worst case. Larger systems add indexing structures to reduce lookup cost.

\section{File allocation on storage}
The OS/file system must map a file's logical blocks to physical storage blocks.
\begin{itemize}
  \item \term{Contiguous allocation}: file occupies consecutive blocks. Fast sequential/random access, but growth and external fragmentation are concerns.
  \item \term{Linked allocation}: each block points to the next. Easy growth and no external fragmentation, but random access is inefficient and pointer integrity matters.
  \item \term{Indexed allocation}: a dedicated index block stores pointers to the file's data blocks. Supports direct access but consumes index space.
\end{itemize}

\begin{pitfall}
Using \texttt{goto START} after discovering a conflict can leave earlier temporary choices or the index-block mark in an inconsistent state unless rollback is carefully implemented. Transaction-like allocation should validate the whole request before committing state changes.
\end{pitfall}

\section{Durability and consistency}
Real file systems must survive partial writes and crashes. Journaling, copy-on-write, checksums, write ordering, and recovery tools are examples of mechanisms used to keep metadata and file content consistent.

\begin{chapterrecap}
\begin{itemize}
  \item Text and binary files encode records differently and have different portability trade-offs.
  \item Sequential search is simple but scales linearly with record count.
  \item Contiguous, linked, and indexed allocation trade placement simplicity, access speed, growth flexibility, and metadata overhead.
