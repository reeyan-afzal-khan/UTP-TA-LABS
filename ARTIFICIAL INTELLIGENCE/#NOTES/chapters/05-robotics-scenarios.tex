\section{Scenario 1: simple 2D robot motion}

The first simulation starts at \((x,y)=(0,0)\), sets the orientation to \(45^\circ\), and moves with constant speed. The update rule in the source is
\[
x\leftarrow x+v\cos(\theta)\Delta t,
\qquad
 y\leftarrow y+v\sin(\theta)\Delta t,
\]
with \(\Delta t=0.1\).

\begin{lstlisting}[style=mlpython]
import numpy as np
import matplotlib.pyplot as plt

x, y = 0, 0
theta = np.pi / 4
v = 1
time = np.linspace(0, 10, 100)
x_path, y_path = [], []

for t in time:
    x += v * np.cos(theta) * 0.1
    y += v * np.sin(theta) * 0.1
    x_path.append(x)
    y_path.append(y)

plt.plot(x_path, y_path, label='Robot Path')
plt.title('Simple 2D Robot Motion')
plt.xlabel('X')
plt.ylabel('Y')
plt.legend()
plt.grid(True)
plt.axis('equal')
plt.show()
\end{lstlisting}

\begin{intuition}
The robot's ``intelligence'' in this first scenario is deliberately minimal. The point is to establish state and motion: the current position is repeatedly updated from velocity and orientation, producing a trajectory that later controllers can modify.
\end{intuition}

\section{Scenario 2: obstacle avoidance by a reactive rule}

The second scenario stores four discrete directions and checks whether the next cell is in a set of static obstacles. If an obstacle is detected, the direction index is advanced by one, which the source describes as a 90-degree clockwise turn.

\begin{lstlisting}[style=mlpython]
x, y = [0], [0]
directions = [(1, 0), (0, 1), (-1, 0), (0, -1)]
dir_index = 0
obstacles = {(3, 0), (4, 0), (0, 5)}

for _ in range(15):
    next_x = x[-1] + directions[dir_index][0]
    next_y = y[-1] + directions[dir_index][1]

    if (next_x, next_y) in obstacles:
        dir_index = (dir_index + 1) % 4
        continue

    x.append(next_x)
    y.append(next_y)
\end{lstlisting}

\begin{keyidea}
This is a reactive controller: it does not compute a complete route to a goal. It senses a local condition (the next cell is blocked) and immediately changes the action.
\end{keyidea}

\section{Scenario 3: line following with PID feedback}

The line-following example defines a desired sinusoidal path
\[
y_{\text{desired}}=8\sin(0.1x)
\]
and updates the robot's vertical position using three error terms.

\begin{mltable}
\begin{tabularx}{\linewidth}{@{}>{\bfseries\leavevmode\color{MLNavy}}p{0.18\linewidth}p{0.20\linewidth}X@{}}
\toprule
\rowcolor{MLPaleBlue!92}
Term & Source variable & Role in the update \\
\midrule
Proportional & \texttt{Kp * error} & Responds to the current difference between desired and actual path. \\
Integral & \texttt{Ki * error\_sum} & Uses the accumulated error. \\
Derivative & \texttt{Kd * derivative} & Uses the change in error from the previous step. \\
\bottomrule
\end{tabularx}
\end{mltable}

The source update is
\[
y_{robot}\leftarrow y_{robot}+K_p e+K_i\sum e+K_d(e-e_{prev}).
\]

\begin{lstlisting}[style=mlpython]
Kp = 0.5
Ki = 0.01
Kd = 0.1

y_robot = 0
error_sum = 0
prev_error = 0
y_path = []

for i in range(len(x)):
    error = y_desired[i] - y_robot
    error_sum += error
    derivative = error - prev_error
    y_robot += Kp * error + Ki * error_sum + Kd * derivative
    prev_error = error
    y_path.append(y_robot)
\end{lstlisting}

\section{Scenario 4: path planning with A*}

The robotics handout reuses A* on a grid with obstacles. The open list is a priority queue, the path cost increments by 1 for each move, and Manhattan distance is the heuristic.

\begin{lstlisting}[style=mlpython]
import heapq

def heuristic(a, b):
    return abs(a[0] - b[0]) + abs(a[1] - b[1])

def a_star(grid, start, goal):
    open_list = []
    heapq.heappush(
        open_list,
        (heuristic(start, goal), 0, start, [])
    )
    visited = set()

    while open_list:
        _, cost, current, path = heapq.heappop(open_list)
        if current in visited:
            continue
        visited.add(current)
        path = path + [current]

        if current == goal:
            return path

        for dx, dy in [(0, 1), (1, 0), (-1, 0), (0, -1)]:
            nx, ny = current[0] + dx, current[1] + dy
            if 0 <= nx < len(grid) and 0 <= ny < len(grid[0]):
                if grid[nx][ny] == 0:
                    heapq.heappush(
                        open_list,
                        (cost + 1 + heuristic((nx, ny), goal),
                         cost + 1,
                         (nx, ny),
                         path)
                    )
    return []
\end{lstlisting}

\begin{intuition}
The search algorithm is the same idea as Chapter 2, but the state now has a physical interpretation: each node in the search graph is a possible robot location in the workspace grid.
\end{intuition}

\section{Scenario 5: two robots avoiding collision}

Two robots begin at opposite corners and move toward one another. The source checks the coordinate-wise separation:

\begin{lstlisting}[style=mlpython]
if abs(r1[0] - r2[0]) <= 1 and abs(r1[1] - r2[1]) <= 1:
    dx1 = dy1 = dx2 = dy2 = 0
\end{lstlisting}

When the robots are close enough according to this rule, both movement commands are set to zero.

\begin{pitfall}
This simulation uses a very simple stopping rule. It demonstrates the logic of collision detection and response, not a full multi-robot planning system. Its value in the course is that the condition-action pattern is explicit and easy to visualize.
\end{pitfall}

\section{Scenario 6: a 2-link planar arm}

The handout computes forward kinematics for links of lengths \(l_1=5\) and \(l_2=3\). If the joint angles are \(\theta_1\) and \(\theta_2\), then
\begin{align*}
x_{elbow}&=l_1\cos\theta_1,
&y_{elbow}&=l_1\sin\theta_1,\\
x_{tip}&=x_{elbow}+l_2\cos(\theta_1+\theta_2),
&y_{tip}&=y_{elbow}+l_2\sin(\theta_1+\theta_2).
\end{align*}

\begin{lstlisting}[style=mlpython]
l1, l2 = 5, 3
theta1_range = np.linspace(0, np.pi, 100)
theta2_range = np.linspace(0, np.pi/2, 100)

x2, y2 = [], []
for t1, t2 in zip(theta1_range, theta2_range):
    x_elbow = l1 * np.cos(t1)
    y_elbow = l1 * np.sin(t1)
    x_tip = x_elbow + l2 * np.cos(t1 + t2)
    y_tip = y_elbow + l2 * np.sin(t1 + t2)
    x2.append(x_tip)
    y2.append(y_tip)
\end{lstlisting}
