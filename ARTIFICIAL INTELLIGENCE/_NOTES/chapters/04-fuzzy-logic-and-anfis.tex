Lab 4 introduces \term{approximate reasoning}: fuzzy logic represents concepts such as ``cold'' or ``hot'' with degrees between 0 and 1.

\section{From crisp truth to fuzzy membership}

In classical logic, a statement is either false \((0)\) or true \((1)\). In fuzzy logic, a degree can lie anywhere in the interval
\[
0\leq \mu(x)\leq 1.
\]
For example, ``the water is hot'' may have membership \(0.7\).

\begin{intuition}
Human descriptions often use graded language: somewhat cold, very fast, mostly full. Fuzzy logic turns that kind of gradual description into numerical membership values that a rule system can process.
\end{intuition}

\figref{fig:crisp-fuzzy} shows the difference. A crisp set has a cliff: not hot at
$29.9^\circ$, fully hot at $30.0^\circ$. A fuzzy set replaces it with a ramp, so a small
change in temperature produces a small change in membership. That continuity is the practical
advantage: it stops a controller juddering when a reading hovers near a threshold.

\section{Why fuzzy logic is used}

Fuzzy logic supports:
\begin{itemize}
  \item handle uncertainty, imprecision, and approximate reasoning;
  \item support human-like linguistic rules;
  \item build decision and control systems for applications such as diagnosis and pattern recognition.
\end{itemize}

\section{Membership functions in the temperature controller}

The MATLAB example creates one input, \texttt{Temperature}, over \([0,100]\) and gives it three triangular membership functions: Cold, Warm, and Hot. The output \texttt{FanSpeed}, over \([0,10]\), receives Low, Medium, and High membership functions.

\begin{lstlisting}[style=mlmatlab]
fis = mamfis('Name', 'temperatureControl');

fis = addInput(fis, [0 100], 'Name', 'Temperature');
fis = addMF(fis, 'Temperature', 'trimf', [0 0 50], ...
    'Name', 'Cold');
fis = addMF(fis, 'Temperature', 'trimf', [25 50 75], ...
    'Name', 'Warm');
fis = addMF(fis, 'Temperature', 'trimf', [50 100 100], ...
    'Name', 'Hot');

fis = addOutput(fis, [0 10], 'Name', 'FanSpeed');
fis = addMF(fis, 'FanSpeed', 'trimf', [0 0 5], ...
    'Name', 'Low');
fis = addMF(fis, 'FanSpeed', 'trimf', [3 5 7], ...
    'Name', 'Medium');
fis = addMF(fis, 'FanSpeed', 'trimf', [5 10 10], ...
    'Name', 'High');
\end{lstlisting}

The rule list maps each input term to its corresponding output term.

\begin{lstlisting}[style=mlmatlab]
ruleList = [
    1 1 1 1;  % IF Cold THEN Low
    2 2 1 1;  % IF Warm THEN Medium
    3 3 1 1   % IF Hot THEN High
];
fis = addRule(fis, ruleList);

fanSpeed = evalfis(fis, 70);
fprintf('Fan speed at 70 C: %.2f\n', fanSpeed);
figure;
gensurf(fis);
\end{lstlisting}

\begin{workedexample}
At \(70^\circ\mathrm{C}\), the triangular definitions give
\[
\mu_{Cold}(70)=0,\qquad
\mu_{Warm}(70)=\frac{75-70}{75-50}=0.2,\qquad
\mu_{Hot}(70)=\frac{70-50}{100-50}=0.4.
\]
The Medium and High rules fire at strengths 0.2 and 0.4. Default Mamdani inference with centroid defuzzification produces a fan speed of approximately \(7.16\) on the \([0,10]\) scale.
\end{workedexample}

The Sugeno example creates a \texttt{Speed} input and a \texttt{BrakeForce} output, with Gaussian input membership functions and linear output functions.

\begin{lstlisting}[style=mlmatlab]
fis2 = sugfis('Name', 'speedControl');
fis2 = addInput(fis2, [0 100], 'Name', 'Speed');
fis2 = addOutput(fis2, [0 1], 'Name', 'BrakeForce');

fis2 = addMF(fis2, 'Speed', 'gaussmf', [10 20], 'Name', 'Slow');
fis2 = addMF(fis2, 'Speed', 'gaussmf', [10 80], 'Name', 'Fast');
fis2 = addMF(fis2, 'BrakeForce', 'linear', [0.002 0.1], 'Name', 'Low');
fis2 = addMF(fis2, 'BrakeForce', 'linear', [0.006 0.3], 'Name', 'High');

ruleList2 = [
    1 1 1 1;  % IF Speed is Slow THEN BrakeForce is Low
    2 2 1 1   % IF Speed is Fast THEN BrakeForce is High
];
fis2 = addRule(fis2, ruleList2);

brakeForce = evalfis(fis2, 60);
fprintf('Brake force at speed 60: %.3f\n', brakeForce);
\end{lstlisting}

Each Sugeno rule produces a constant or linear value; the FIS returns their firing-strength-weighted average. For a \texttt{linear} output MF with one input, MATLAB reads the parameters \([a\;b]\) as the function \(a\times\text{Speed}+b\).

At speed 60 the Gaussian memberships are \(\mu_{Slow}=0.0003\) and \(\mu_{Fast}=0.1353\), so the Fast rule dominates:
\[
\text{BrakeForce}=\frac{0.0003\times0.22+0.1353\times0.66}{0.0003+0.1353}\approx0.659.
\]

\begin{pitfall}
\textbf{Read the consequent function, not the rule's name.} A rule labelled ``High'' whose function is \(-0.01\times\text{Speed}+1\) still \emph{decreases} with speed: it returns 1.0 at a standstill and 0.0 at 100. The label says high; the arithmetic says the opposite, and the arithmetic wins.

An earlier version of the supplied \texttt{Lab\_4\_code.m} used exactly those coefficients, giving
\[
\text{BrakeForce}(20)=0.200,\quad
\text{BrakeForce}(60)=0.400,\quad
\text{BrakeForce}(100)=0.000,
\]
a controller that brakes hardest when parked and not at all at top speed. Every MATLAB call succeeded. The code was valid and the model was wrong.

The file now uses \([0.002\;0.1]\) and \([0.006\;0.3]\), so both consequents rise with speed and the numbers above hold.
\end{pitfall}

\begin{tryit}
Never judge a controller from one input value. Evaluate it across the whole range and look at the shape:

\begin{lstlisting}[style=mlmatlab]
evalfis(fis2, [0; 20; 40; 60; 80; 100])
gensurf(fis2);
\end{lstlisting}

A monotonic rise from about 0.10 to 0.90 is what this design intends. Anything non-monotonic, flat, or falling means a consequent slopes the wrong way --- the failure a single \texttt{evalfis(fis2, 60)} would have hidden completely.
\end{tryit}

\section{ANFIS: Adaptive Neuro-Fuzzy Inference System}

ANFIS can be summarized as
\[
\text{ANFIS}=\text{neural-network learning}+\text{fuzzy-logic representation}.
\]
It uses a Sugeno FIS and learns rule and membership-function parameters from data, commonly through least squares and gradient descent.

\figref{fig:anfis} unpacks that sum. The five layers are the stages of
\figref{fig:fis-pipeline} redrawn as a network. Once each stage is a differentiable node, the
membership shapes and rule outputs become parameters gradient descent can adjust. The fuzzy
reasoning is unchanged --- only who chooses the numbers.

\section{Training examples in Lab 4}

The examples cover one- and two-input training, prediction, FIS persistence, error analysis, and air-conditioning control.

\begin{lstlisting}[style=mlmatlab]
% Single input
data1 = [0 0; 5 2.5; 10 5; 15 7.5; 20 10];
anfisFIS1 = anfis(data1, 10);

% Two inputs
data2 = [0 0 0; 5 2 2.5; 10 5 5; 15 7 7.5; 20 10 10];
anfisFIS2 = anfis(data2, 20);

% Prediction
inputVal = [12 6];
predictedOutput = evalfis(anfisFIS2, inputVal);

\end{lstlisting}

ANFIS interprets the final column as the target. Thus, \texttt{data1} contains one input and one output, whereas \texttt{data2} contains two inputs and one output. A prediction row contains inputs only: \texttt{[12 6]}, without a placeholder for the unknown output.

\begin{pitfall}
Five rows demonstrate the application programming interface (API), not generalization. Evaluate separate validation data before making performance claims.
\end{pitfall}

\subsection{Scaling the diabetes data: two traps}

The final ANFIS example trains on \texttt{diabetes.csv}, whose first eight columns are measurements and whose ninth (\texttt{Outcome}) is a 0/1 label.

\begin{pitfall}
\textbf{\texttt{normalize(X)} is not ``scale to \([0,1]\)''.} With no options MATLAB performs \emph{z-score} standardisation, giving mean 0 and standard deviation 1. Applied to the whole matrix it also rescales the label column, turning the 0/1 outcome into \(\{-0.732,\,1.365\}\) --- no longer a label at all.

The option that actually produces \([0,1]\) is \texttt{normalize(X,'range')}, and it belongs on the features only:

\begin{lstlisting}[style=mlmatlab]
features = normalize(data3(:, 1:8), 'range');   % -> [0, 1]
labels   = data3(:, 9);                         % left as 0/1
\end{lstlisting}
\end{pitfall}

\begin{pitfall}
\textbf{A physically impossible zero is this dataset's missing-value code.} Insulin is 0 in 374 of 768 rows (49\%) and SkinThickness in 227 (30\%); BloodPressure, BMI and Glucose also contain zeros. Nobody has a blood pressure of zero.

Left as numbers they drag every mean and every membership function toward zero. Check before modelling:

\begin{lstlisting}[style=mlmatlab]
sum(data3 == 0)
\end{lstlisting}

Then say in your report which columns you treated as missing and what you did about them.
\end{pitfall}

\begin{keyidea}
ANFIS regresses the 0/1 label, so its output is continuous. Turning that into a class needs a \emph{threshold}, and 0.5 is a choice rather than a law. Compare the result against the majority-class baseline: 500 of 768 patients have Outcome 0, so always predicting 0 already scores about 65\%. A model that cannot beat that has learned nothing worth reporting.
\end{keyidea}

\begin{chapterrecap}
\begin{itemize}
  \item Fuzzy logic represents degrees of truth between 0 and 1.
  \item A FIS consists of fuzzification, a rule base, an inference engine, and defuzzification.
  \item Mamdani systems aggregate fuzzy outputs; Sugeno systems use constant or linear consequents.
  \item ANFIS combines Sugeno fuzzy inference with data-driven learning.
\end{itemize}
