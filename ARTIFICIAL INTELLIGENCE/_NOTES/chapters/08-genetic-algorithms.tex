\section{The GA workflow}

The workflow is:

\begin{mlsteps}
  \item Initialize a population randomly.
  \item Evaluate the fitness of every individual.
  \item Select parents based on fitness.
  \item Apply crossover and mutation to create a new population.
  \item Replace the old population with the new generation.
  \item Repeat until convergence or the maximum generation count is reached.
\end{mlsteps}

\begin{keyidea}
A GA transforms a population: selection favors fitter candidates, crossover recombines them, and mutation adds variation.
\end{keyidea}

\subsection{Roulette-wheel selection}

Fitness values define selection probabilities:
\[
p_i=\frac{f_i}{\sum_j f_j},
\]
then uses cumulative probabilities and a uniform random number to select each parent.

This formula requires nonnegative selection scores with a positive total. If an objective can be negative or if every score is zero, transform or shift the scores before normalizing them.

\figref{fig:roulette} shows the mechanism. Each individual gets an arc proportional to its
fitness and one random draw picks the owner. Fitter individuals win more often, but weak ones
are never eliminated --- keeping them preserves the diversity a later crossover may need.

\subsection{Arithmetic crossover and mutation}

The continuous examples blend two parents with a random coefficient \(\alpha\), then occasionally add a small random perturbation.

\figref{fig:crossover} contrasts the two continuous operators with the binary
single-point crossover used for the knapsack problem in Code~4. Arithmetic crossover produces
a child \emph{between} its parents, so a population can only ever contract toward the region
it already occupies; mutation is what lets it reach outside.

\subsection{Complete runnable loop}

The complete program combines initialization, evaluation, variation, replacement, reporting, and plotting.

\begin{lstlisting}[style=mlmatlab]
rng(7);                         % reproducible teaching run
popSize = 20;
maxGen = 50;
crossRate = 0.8;
mutRate = 0.1;
pop = rand(popSize, 1);
fitnessFunc = @(x) x .* sin(10*pi*x) + 1;

bestHistory = zeros(maxGen, 1);
bestEverFitness = -Inf;
bestEverX = NaN;

for gen = 1:maxGen
    fitness = fitnessFunc(pop);
    [bestHistory(gen), bestIndex] = max(fitness);
    if bestHistory(gen) > bestEverFitness
        bestEverFitness = bestHistory(gen);
        bestEverX = pop(bestIndex);
    end

    probability = fitness / sum(fitness);
    cumulative = cumsum(probability);
    parents = zeros(size(pop));
    for i = 1:popSize
        index = find(cumulative >= rand, 1, 'first');
        parents(i) = pop(index);
    end

    offspring = parents;
    for i = 1:2:popSize
        if rand < crossRate
            alpha = rand;
            p1 = parents(i);
            p2 = parents(i+1);
            offspring(i) = alpha*p1 + (1-alpha)*p2;
            offspring(i+1) = alpha*p2 + (1-alpha)*p1;
        end
    end

    mutate = rand(size(offspring)) < mutRate;
    offspring(mutate) = offspring(mutate) + ...
        0.05*randn(sum(mutate(:)), 1);
    pop = min(max(offspring, 0), 1);
end

fprintf('Best x: %.5f, f(x): %.5f\n', ...
    bestEverX, bestEverFitness);
plot(bestHistory, 'LineWidth', 1.5);
xlabel('Generation'); ylabel('Best fitness in generation');
grid on;
\end{lstlisting}

The global maximum is near \(x=0.85119\), where \(f(x)\approx1.85060\); a short stochastic run may not reproduce it exactly.

\begin{workedexample}
If three candidates have fitness \([1,2,1]\), their roulette probabilities are \([0.25,0.50,0.25]\), and their cumulative probabilities are \([0.25,0.75,1.00]\). A random draw \(r=0.60\) selects the second candidate because 0.75 is the first cumulative value at least as large as 0.60.
\end{workedexample}

\section{Code 2: minimize the Rosenbrock function}

The second problem minimizes
\[
f(x,y)=(1-x)^2+100(y-x^2)^2,
\qquad x,y\in[-2,2].
\]
Because roulette-wheel selection in the example expects larger values to be more desirable, the source inverts the minimization fitness:
\[
\text{invFitness}=\frac{1}{f+10^{-6}}.
\]

\begin{lstlisting}[style=mlmatlab]
pop = -2 + 4*rand(popSize, 2);  % both genes in [-2, 2]
fitnessFunc = @(v) (1 - v(:,1)).^2 + ...
    100*(v(:,2) - v(:,1).^2).^2;

fitness = fitnessFunc(pop);
invFitness = 1 ./ (fitness + 1e-6);
prob = invFitness / sum(invFitness);

mutate = rand(size(newPop)) < mutRate;
newPop(mutate) = newPop(mutate) + ...
    0.05*randn(sum(mutate(:)), 1);
newPop = min(max(newPop, -2), 2);
\end{lstlisting}

The mutation step adds Gaussian noise and clips each variable back to \([-2,2]\). The known optimum is \((x,y)=(1,1)\), where the objective is zero; this gives a direct correctness check for the final chromosome.

\section{Code 3: optimize linear-regression weights}

The regression example generates noisy data from
\[
y=2.5x+5+\text{noise}
\]
and represents each chromosome as two real-valued genes, \(w_1\) and \(w_2\). The objective is mean squared error (MSE):
\[
\mathrm{MSE}(w_1,w_2)=\operatorname{mean}
\left(y-(w_1x+w_2)\right)^2.
\]

\begin{lstlisting}[style=mlmatlab]
rng(7);
x = linspace(0, 10, 100)';
true_w = [2.5, 5];
y = true_w(1)*x + true_w(2) + randn(size(x));

pop = [5*rand(popSize, 1), 10*rand(popSize, 1)];
mse = zeros(popSize, 1);
for i = 1:popSize
    prediction = pop(i,1)*x + pop(i,2);
    mse(i) = mean((y - prediction).^2);
end
selectionScore = 1 ./ (mse + 1e-6);
\end{lstlisting}

A chromosome may encode model parameters directly. Evaluate \texttt{pop(i,1)} and \texttt{pop(i,2)} from the same row to avoid shape errors.

\begin{lstlisting}[style=mlmatlab]
weights = [2 3 4 5];
values = [3 4 5 8];
capacity = 5;

chromLength = length(weights);
pop = round(rand(popSize, chromLength));

fitness = zeros(popSize, 1);
for i = 1:popSize
    totalWeight = sum(pop(i,:) .* weights);
    totalValue = sum(pop(i,:) .* values);
    if totalWeight <= capacity
        fitness(i) = totalValue;
    end
end
\end{lstlisting}

Feasible chromosomes receive total value as fitness; overweight chromosomes receive zero. Mutation flips one bit:

\begin{lstlisting}[style=mlmatlab]
gene = randi(chromLength);
newPop(i, gene) = 1 - newPop(i, gene);
\end{lstlisting}

\begin{workedexample}
Chromosome \([1,1,0,0]\) selects items 1 and 2, giving weight \(2+3=5\) and value \(3+4=7\). Chromosome \([0,0,0,1]\) selects item 4, giving weight 5 and value 8. The latter is the optimum for this four-item instance. Chromosome \([1,0,1,0]\) has weight 6 and therefore receives fitness zero under the stated penalty rule.
\end{workedexample}

\begin{intuition}
Continuous optimization mutates a number by adding a small perturbation. Binary optimization mutates a decision by flipping 0 to 1 or 1 to 0. The GA framework is the same; the chromosome representation determines the appropriate operator.
\end{intuition}

\section{Code 5: find roots through minimization}

The final problem minimizes
\[
f(x)=(x-3)^2(x+2)^2,
\qquad x\in[-5,5].
\]
The objective is zero at \(x=3\) and \(x=-2\). Negating and shifting it produces nonnegative roulette-wheel selection scores.

\begin{lstlisting}[style=mlmatlab]
pop = -5 + 10*rand(popSize, 1);
fitnessFunc = @(x) (x - 3).^2 .* (x + 2).^2;
fitness = -fitnessFunc(pop);

prob = fitness - min(fitness) + eps;
prob = prob / sum(prob);
\end{lstlisting}

Because both \(-2\) and 3 produce objective zero, separate runs may converge to different correct roots. Report the final objective as well as \(x\): a value near a root with a visibly nonzero objective remains an imprecise solution.

\section{Elitism in the concept list versus the supplied code}

\term{Elitism} copies the current best solution unchanged into the next generation. The supplied loops omit this step, so generation-best fitness need not be monotonic.
