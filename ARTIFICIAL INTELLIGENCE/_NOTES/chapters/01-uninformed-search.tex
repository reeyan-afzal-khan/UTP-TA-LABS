The first laboratory introduces Breadth-First Search (BFS), Depth-First Search (DFS), and Uniform-Cost Search (UCS). These \term{uninformed} methods use no estimate of remaining distance; they differ in frontier order.

\section{A search problem is more than a graph}

The exercises use graphs, mazes, word transformations, and binary trees. These domains look different, but each can be expressed with the same ingredients.

\begin{intuition}
A search algorithm needs only a successor function and a rule for selecting the next frontier state; the state may represent a city, word, or maze cell.
\end{intuition}

\section{The frontier and the visited set}

Most graph-search implementations maintain two central structures.

\begin{description}
  \item[Frontier] States that have been discovered but not fully explored. The data structure used for this frontier gives BFS, DFS, and UCS their characteristic behavior.
  \item[Visited set] States already processed. It prevents repeated work and is essential when the graph contains cycles or loops.
\end{description}

\section{Breadth-First Search}

\term{Breadth-First Search} expands states level by level. From \texttt{A}, it processes \texttt{B} and \texttt{C} before deeper states.

A first-in, first-out (FIFO) queue implements this rule:

\begin{mlsteps}
  \item Put the start state in the queue.
  \item Remove the oldest state from the front.
  \item If it is the goal, return its path.
  \item Add unvisited successors to the back of the queue.
  \item Repeat until the queue is empty.
\end{mlsteps}

For the unweighted graph from Lab 1,
\[
A\rightarrow\{B,C\},\quad B\rightarrow\{D,E\},\quad C\rightarrow\{F\},
\]
with \(D,E,F\rightarrow G\), BFS returns a path with the fewest edges because every step is treated as equal cost.

\begin{workedexample}
With the stated neighbor order, BFS expands \texttt{A}, \texttt{B}, and \texttt{C} before the next layer; \texttt{D} then yields the path \texttt{A -> B -> D -> G}.

The queue trace below separates the state being expanded from the paths still waiting. The leftmost path is removed next.
\[
\begin{array}{c|l}
\text{expand} & \text{frontier after expansion} \\
\hline
A & [A,B],\ [A,C] \\
B & [A,C],\ [A,B,D],\ [A,B,E] \\
C & [A,B,D],\ [A,B,E],\ [A,C,F] \\
D & [A,B,E],\ [A,C,F],\ [A,B,D,G]
\end{array}
\]
The returned path has three edges and is selected by queue order, not a distance estimate.
\end{workedexample}

\subsection{BFS in a maze}

The maze exercise uses four-direction movement. A cell is a state, and a legal successor is an in-bounds adjacent cell that is not a wall. BFS is suitable when every move has equal cost and the objective is the shortest number of steps.

\begin{lstlisting}[style=mlpython]
from collections import deque

def bfs_grid(grid, start, goal):
    rows, cols = len(grid), len(grid[0])
    visited = {start}
    queue = deque([(start, [start])])

    while queue:
        (x, y), path = queue.popleft()
        if (x, y) == goal:
            return path

        for dx, dy in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
            nx, ny = x + dx, y + dy
            if (0 <= nx < rows and 0 <= ny < cols
                    and grid[nx][ny] == 0
                    and (nx, ny) not in visited):
                visited.add((nx, ny))
                queue.append(((nx, ny), path + [(nx, ny)]))
    return None
\end{lstlisting}

\begin{pitfall}
Mark a state visited when it is inserted into the BFS queue, not only when it is removed. Otherwise the same state can be inserted many times by different parents.
\end{pitfall}

\section{Depth-First Search}

\term{Depth-First Search} follows one branch as far as possible before trying alternatives. A stack or recursion naturally implements this behavior.

\begin{mlsteps}
  \item Start at the current state and perform the goal test.
  \item Mark the state visited.
  \item Choose an unvisited successor.
  \item Recurse down that branch.
  \item If the branch fails, return to the previous state and try the next successor.
\end{mlsteps}

The maze implementation expresses this behavior directly through recursion:

\begin{lstlisting}[style=mlpython]
def dfs_maze(grid, x, y, path, visited, goal):
    if (x, y) == goal:
        return path

    visited.add((x, y))
    for dx, dy in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
        nx, ny = x + dx, y + dy
        if (0 <= nx < len(grid) and 0 <= ny < len(grid[0])
                and grid[nx][ny] == 0
                and (nx, ny) not in visited):
            result = dfs_maze(
                grid, nx, ny,
                path + [(nx, ny)],
                visited, goal
            )
            if result:
                return result
    return None
\end{lstlisting}

\begin{intuition}
BFS expands a wavefront; DFS follows one branch. DFS does not guarantee a minimum-edge path.
\end{intuition}

\subsection{DFS preorder on a binary tree}

The Lab 1 tree has root 1, children 2 and 3, and leaves 4--7. Preorder DFS visits the current node before its left and right subtrees:
\[
1,2,4,5,3,6,7.
\]

\begin{lstlisting}[style=mlpython]
def dfs_preorder(root):
    if not root:
        return []
    return [root.val] + dfs_preorder(root.left) + dfs_preorder(root.right)
\end{lstlisting}

\section{Uniform-Cost Search}

\term{Uniform-Cost Search} expands the frontier path with the smallest accumulated cost \(g(n)\), using a min-priority queue instead of BFS's FIFO queue.

UCS assumes nonnegative edge costs; negative costs invalidate its usual visited-set logic.

For the weighted Lab 1 graph,
\begin{align*}
A&\to B:1, & A&\to C:4,\\
B&\to D:3, & B&\to E:2, & C&\to F:5,\\
D&\to G:4, & E&\to G:1, & F&\to G:2.
\end{align*}
The path through \texttt{B} and \texttt{E} has cost
\[
1+2+1=4,
\]
which is lower than the alternatives shown in the handout.

\begin{workedexample}
UCS starts with \((0,A)\). Expanding \(A\) inserts \((1,B)\) and \((4,C)\); expanding \(B\) inserts \((4,D)\) and \((3,E)\). It therefore selects \(E\) before \(C\), inserts \((4,G)\), and returns \texttt{A -> B -> E -> G} with optimal cost 4. Equal-cost tie order does not affect that minimum cost.
\end{workedexample}

\begin{lstlisting}[style=mlpython]
import heapq

def ucs(graph, start, goal):
    pq = [(0, [start])]
    visited = set()

    while pq:
        cost, path = heapq.heappop(pq)
        node = path[-1]
        if node == goal:
            return path, cost

        if node not in visited:
            visited.add(node)
            for neighbor, weight in graph[node]:
                heapq.heappush(
                    pq,
                    (cost + weight, path + [neighbor])
                )
    return None
\end{lstlisting}

\begin{keyidea}
BFS orders the frontier by depth, DFS by recency/depth, and UCS by accumulated path cost. The graph representation may stay the same while only the frontier policy changes.
\end{keyidea}

\begin{quickcheck}
\begin{enumerate}
  \item Why does BFS ignore the numerical edge weights in the first graph problem?
  \item What changes in the data structure when moving from BFS to UCS?
  \item Why is a visited set especially important for the ``graph with loops'' UCS problem?
  \item What traversal order does DFS preorder produce for the seven-node binary tree in Lab 1?
\end{enumerate}
\end{quickcheck}

\begin{checkanswers}
\begin{enumerate}
  \item BFS treats every edge as one step, so numerical weights are outside its ordering rule.
  \item Replace the FIFO queue with a min-priority queue ordered by cumulative cost \(g\).
  \item Without a visited or best-cost record, loop edges continually create longer cyclic paths.
  \item \(1,2,4,5,3,6,7\).
\end{enumerate}
\end{checkanswers}

\begin{chapterrecap}
\begin{itemize}
  \item Search problems specify states, successors, a start, a goal test, and optionally path costs.
  \item BFS uses a FIFO queue and is suited to equal-cost shortest-path problems.
  \item DFS follows one branch before backtracking, using recursion or a stack.
  \item UCS uses a priority queue ordered by cumulative cost.
\end{itemize}
\end{chapterrecap}
