Lab 2 introduces a \term{heuristic}: an estimate of remaining distance or cost used to guide the frontier.

\section{Heuristic search}

Let \(h(n)\) denote the heuristic value of node \(n\). Smaller values in the laboratory examples mean ``looks closer to the goal.'' The goal itself has \(h(G)=0\).

\begin{mltable}
\begin{tabularx}{\linewidth}{@{}>{\bfseries\leavevmode\color{MLNavy}}p{0.18\linewidth}p{0.22\linewidth}X@{}}
\toprule
\rowcolor{MLPaleBlue!92}
Quantity & Meaning & Used by \\
\midrule
\(g(n)\) & Actual path cost accumulated from the start to node \(n\) & UCS and A* \\
\(h(n)\) & Estimated remaining cost or distance from \(n\) to the goal & GBFS and A* \\
\(f(n)\) & \(g(n)+h(n)\), an estimated total cost through \(n\) & A* \\
\bottomrule
\end{tabularx}
\end{mltable}

\begin{keyidea}
Greedy Best-First Search asks, ``Which frontier state appears closest to the goal?'' A* asks, ``Which frontier state gives the best combination of cost already paid and estimated cost still remaining?''
\end{keyidea}

\section{Greedy Best-First Search}

\term{Greedy Best-First Search (GBFS)} orders the frontier by heuristic value only. It ignores the cost already spent reaching a node.

The Lab 2 graph assigns
\[
h(A)=6,\; h(B)=4,\; h(C)=5,\; h(D)=2,\; h(E)=3,\; h(F)=2,\; h(G)=0.
\]
From \texttt{A}, the handout chooses \texttt{B} because \(h(B)=4<h(C)=5\). From \texttt{B}, it prefers \texttt{D} because \(h(D)=2<h(E)=3\). Since \texttt{D} is a dead end, the search later explores another frontier state and eventually reaches \texttt{G} through \texttt{E}.

\begin{lstlisting}[style=mlpython]
import heapq

def greedy_best_first(graph, heuristic, start, goal):
    pq = [(heuristic[start], [start])]
    visited = set()

    while pq:
        _, path = heapq.heappop(pq)
        node = path[-1]
        if node == goal:
            return path

        if node in visited:
            continue
        visited.add(node)

        for neighbor in graph[node]:
            if neighbor not in visited:
                heapq.heappush(
                    pq,
                    (heuristic[neighbor], path + [neighbor])
                )
    return None
\end{lstlisting}

\begin{pitfall}
GBFS may prefer a low-heuristic state reached by an expensive path because it ranks only \(h(n)\).
\end{pitfall}

\section{Manhattan distance in a grid}

The Lab 2 robot-maze problem uses the Manhattan-distance heuristic. For two grid coordinates \(a=(x_a,y_a)\) and \(b=(x_b,y_b)\),
\[
h(a,b)=|x_a-x_b|+|y_a-y_b|.
\]
It measures how many horizontal and vertical coordinate differences remain when diagonal movement is not used.

\begin{lstlisting}[style=mlpython]
def manhattan(a, b):
    return abs(a[0] - b[0]) + abs(a[1] - b[1])
\end{lstlisting}

\begin{workedexample}
For start \((0,0)\) and goal \((3,3)\), the start heuristic is \(6\). A move to \((0,1)\) reduces the heuristic to \(5\). GBFS repeatedly prefers frontier positions with the smallest remaining Manhattan distance, subject to walls and the positions already explored.
\end{workedexample}

\section{Word-ladder heuristic}

For the Lab 2 word ladder, the heuristic is the number of letters that differ from the goal word. If the goal is \texttt{cog}, then \texttt{dog} differs in one position while \texttt{dot} differs in two positions.

\begin{lstlisting}[style=mlpython]
def word_h(word, goal):
    return sum(a != b for a, b in zip(word, goal))
\end{lstlisting}

The representation changes from coordinates to strings, but \(h(n)\) retains the same role.

\section{A* Search}

\term{A* Search} combines actual and estimated cost:
\[
f(n)=g(n)+h(n).
\]
Here, \(g(n)\) penalizes costly paths while \(h(n)\) guides the search toward the goal.

\begin{workedexample}
Suppose \(X\) has \((g,h)=(5,3)\) and \(Y\) has \((1,5)\). GBFS chooses \(X\) because \(3<5\); A* chooses \(Y\) because \(f(Y)=6<f(X)=8\).
\end{workedexample}

For A* to guarantee an optimal result, the heuristic must not overestimate the cheapest remaining cost. Such a heuristic is \term{admissible}. A commonly used stronger condition is \term{consistency}: for every edge \(n\to n'\) of cost \(c\),
\[
h(n)\leq c+h(n').
\]
Manhattan distance is consistent for four-direction movement when every move costs at least one. If moves can cost less than one, scale the heuristic by the minimum possible move cost.

For the supplied graph:
\begin{align*}
A&\to B:1, & A&\to C:4,\\
B&\to D:3, & B&\to E:1,\\
E&\to G:2, & C&\to F:5, & F&\to G:1.
\end{align*}
with the handout's heuristic
\[
h(A)=7,\; h(B)=6,\; h(C)=4,\; h(D)=3,\; h(E)=2,\; h(F)=2,\; h(G)=0.
\]
The optimal route is
\[
A\to B\to E\to G
\]
with path cost \(1+1+2=4\).

\subsection{Is that heuristic admissible? Check, do not assume}

The condition above is worth applying to the handout's own numbers rather than reading past it. Let \(h^\star(n)\) be the \emph{true} cheapest cost from \(n\) to the goal, obtained by searching backwards from \(G\). Admissibility requires \(h(n)\leq h^\star(n)\) at every node.

\begin{mltable}
\begin{tabularx}{\linewidth}{@{}>{\bfseries\leavevmode\color{MLNavy}}p{0.10\linewidth}p{0.13\linewidth}p{0.15\linewidth}X@{}}
\toprule
\rowcolor{MLPaleBlue!92}
Node & \(h(n)\) & true \(h^\star(n)\) & Admissible? \\
\midrule
A & 7 & 4 & \textbf{no} --- overestimates by 3 \\
B & 6 & 3 & \textbf{no} --- overestimates by 3 \\
C & 4 & 6 & yes \\
D & 3 & --- & \(G\) is unreachable from \(D\) \\
E & 2 & 2 & yes (exact) \\
F & 2 & 1 & \textbf{no} --- overestimates by 1 \\
G & 0 & 0 & yes \\
\bottomrule
\end{tabularx}
\end{mltable}

\begin{pitfall}
This heuristic is \textbf{not admissible}, so A* carries no optimality guarantee on this graph. It still returns \texttt{A -> B -> E -> G} at cost 4, which happens to be optimal --- but that is luck, not proof, and a differently shaped graph with the same style of heuristic can return a worse path.

Report which heuristics in the lab are admissible and which are not. ``A* found it, so it must be optimal'' is exactly the reasoning the admissibility condition exists to prevent.
\end{pitfall}

\begin{tryit}
\texttt{Lab02/search\_informed.py} computes the \(h^\star\) column by running a backwards search from the goal and prints this table, so you can verify the claim instead of taking it on trust.

Then repair the heuristic by scaling every value by a constant \(k\). Admissibility needs \(k\,h(n)\leq h^\star(n)\) at every node, so \(k\) is limited by the worst node:
\[
k\leq\min_n \frac{h^\star(n)}{h(n)}
=\min\left(\tfrac{4}{7},\tfrac{3}{6},\tfrac{6}{4},\tfrac{2}{2},\tfrac{1}{2}\right)=\tfrac12,
\]
with \(B\) and \(F\) both binding. Halving the heuristic makes the whole table read yes. Scaling by \(4/7\) --- the factor that fixes the largest single error, at \(A\) --- is not enough, and checking that for yourself is the point of the exercise.
\end{tryit}

\begin{intuition}
An inadmissible heuristic makes A* behave more like Greedy Best-First Search: it trusts the estimate too much and can commit to a branch before the cost evidence says it should. Admissibility is what keeps the \(g\) term in charge when the two disagree.
\end{intuition}

\subsection{A* implementation pattern}

The Lab 3 reference implementation stores both \(g\) and \(f\) in the heap:

\begin{lstlisting}[style=mlpython]
def astar_graph(graph, heuristic, start, goal):
    import heapq
    pq = [(heuristic[start], 0, [start])]
    best_g = {start: 0}

    while pq:
        f, g, path = heapq.heappop(pq)
        node = path[-1]
        if g > best_g.get(node, float('inf')):
            continue                 # stale, more expensive entry
        if node == goal:
            return path, g

        for neighbor, cost in graph[node]:
            new_g = g + cost
            if new_g < best_g.get(neighbor, float('inf')):
                best_g[neighbor] = new_g
                heapq.heappush(
                    pq,
                    (new_g + heuristic[neighbor],
                     new_g,
                     path + [neighbor])
                )
    return None
\end{lstlisting}

The \texttt{best\_g} dictionary replaces costlier routes and identifies stale queue entries.

\section{A* in a weighted grid}

Lab 2 supplies a \(5\times5\) grid in which each cell contains a movement cost and asks for a path from \((0,0)\) to \((4,4)\). The search cost \(g\) accumulates grid-cell costs, while Manhattan distance supplies \(h\).

\begin{lstlisting}[style=mlpython]
def astar_grid(grid, start, goal):
    import heapq

    def h(a, b):
        return abs(a[0] - b[0]) + abs(a[1] - b[1])

    rows, cols = len(grid), len(grid[0])
    pq = [(h(start, goal), 0, [start])]
    best_g = {start: 0}

    while pq:
        f, g, path = heapq.heappop(pq)
        x, y = path[-1]
        if g > best_g.get((x, y), float('inf')):
            continue
        if (x, y) == goal:
            return path, g

        for dx, dy in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
            nx, ny = x + dx, y + dy
            if 0 <= nx < rows and 0 <= ny < cols:
                new_g = g + grid[nx][ny]
                if new_g < best_g.get((nx, ny), float('inf')):
                    best_g[(nx, ny)] = new_g
                    heapq.heappush(
                        pq,
                        (new_g + h((nx, ny), goal),
                         new_g,
                         path + [(nx, ny)])
                    )
    return None
\end{lstlisting}

\begin{quickcheck}
\begin{enumerate}
  \item What information does GBFS ignore that A* uses?
  \item For a grid state \((2,1)\) and goal \((4,4)\), what is the Manhattan heuristic?
  \item In the Lab 2 A* graph, what is the total cost of \texttt{A -> B -> E -> G}?

\end{enumerate}

\begin{checkanswers}
\begin{enumerate}
  \item GBFS ignores the accumulated path cost \(g(n)\).
  \item \(|2-4|+|1-4|=5\).
  \item \(1+1+2=4\).
  \item The control loop only needs a numerical estimate; each domain defines that estimate from its own representation.
\end{enumerate}
\end{checkanswers}

\begin{chapterrecap}
\begin{itemize}
  \item A heuristic \(h(n)\) estimates remaining distance or cost to the goal.
  \item GBFS orders the frontier by \(h(n)\) and does not include path cost already incurred.
  \item A* orders the frontier by \(f(n)=g(n)+h(n)\).
  \item Manhattan distance guides grids; letter mismatch guides word ladders.
\end{itemize}
\end{chapterrecap}
