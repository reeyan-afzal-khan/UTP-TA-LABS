\labpart{Part A --- Images as tensors}

\begin{labquestion}{2}{Turn images into tensors}
The same digits as Lab~4: each is an $8\times8$ grid of brightness values from 0 to 16. PyTorch works on \emph{tensors}, which are arrays that remember how to compute gradients. A convolutional layer expects images as (batch, channels, height, width), so each row of 64 numbers is reshaped to $1\times8\times8$ and scaled to $[0,1]$. The official test file stays closed until the end; a validation quarter is carved from the training file.
\end{labquestion}

\begin{labquestion}{4}{Write the training loop and train}
The training loop is the whole method. Each epoch shuffles the training rows and walks through them in batches of 32. For each batch: compute the class scores (forward pass), compute the cross-entropy loss, compute every gradient with \texttt{backward()}, and let the optimizer move every weight a small step. After each epoch, accuracy is recorded on the training and validation rows.
\end{labquestion}

\end{lstlisting}
\end{refoutput}

\textbf{What it means.} This is the recipe from Chapter~\ref{ch:orientation}, in eight lines: model, loss, optimizer.

\labpart{Part C --- A convolutional network}

\begin{labquestion}{6}{Build a CNN and trace its shapes}
A CNN keeps the image as a grid. The first layer slides sixteen $3\times3$ filters across it and produces sixteen feature maps; max pooling halves each map; a second layer does the same with thirty-two filters; the result is flattened and classified by a small dense layer. Printing the shape after each stage shows where the numbers go.
\end{labquestion}
\begin{labanswer}

\begin{labquestion}{14}{One solution}
The CNN trained for 5 and for 40 epochs, then a one-block CNN.
\end{labquestion}
\begin{labanswer}
\lstinputlisting[style=utppython,firstline=238,lastline=272]{all_experiments/lab07_deep_learning_cnn_worked.py}
\begin{refoutput}
\begin{lstlisting}[style=utpterminal]
 5 epochs: validation accuracy = 0.9665, test accuracy = 0.9494
40 epochs: validation accuracy = 0.9843, test accuracy = 0.9766
one-block CNN: weights = 17258  test accuracy = 0.9777
two-block CNN: weights = 13706  test accuracy = 0.9705
\end{lstlisting}
\end{refoutput}

\textbf{What it means.} Five epochs are not enough: validation is still rising when training stops. By forty, training accuracy is essentially 1.0, while validation has wobbled between about 0.97 and 0.985 since epoch 10, which is why early stopping keeps the \emph{best} epoch rather than the last. The one-block CNN has more weights, since its flattened vector is 256 rather than 128, and on this run it scores higher. On a GPU the same comparison came out the other way, 0.9705 against 0.9722. So the defensible conclusion is that a second block neither helps nor hurts at $8\times8$, where one pooling already leaves a $4\times4$ map, not that either architecture wins.
\end{labanswer}

\begin{expectedfindings}
\begin{enumerate}
  \item Around 0.94 (0.9405 here), against about 0.957 with ReLU when trained the same way, and against Lab~4's 0.948 for logistic regression. Without an activation the two layers collapse into one linear map, so it is effectively logistic regression with extra steps.
  \item Test accuracy is about 0.933, 0.969, 0.912 and 0.100. The smallest rate is simply slow after 20 epochs. The largest leaves the network at chance level, one digit in ten, which is the overshoot from the practice bowl of Chapter~\ref{ch:learning}.

\begin{troubleshoot}
\begin{description}
  \item[\texttt{No module named 'torch'}] Compare the first line of the Setup output with the environment you installed into. Register the right environment as a kernel, and switch to it.
  \item[\texttt{OMP: Error \#15} on Windows] Two OpenMP runtimes are loaded. The Setup cell sets \texttt{KMP\_DUPLICATE\_LIB\_OK} before importing NumPy; restart the kernel so it takes effect.
  \item[\texttt{mat1 and mat2 shapes cannot be multiplied}] A \texttt{Linear} layer's input size does not match the flattened tensor. Print the shapes with the loop from Question~6.
  \item[\texttt{Invalid device id}] You set \texttt{CUDA\_VISIBLE\_DEVICES} to an empty string. Use \texttt{-1}.
  \item[Tensors on different devices] Use \texttt{.to(DEVICE)} for the model and data, and \texttt{.cpu()} before plotting.
\end{description}
\end{troubleshoot}
