\labsection{7}{Deep learning I: a first neural network and a CNN for images}{sec:lab07-cnn}

\begin{labproject}{Train a dense network and a convolutional network on photos of wood defects}
\textbf{Read first.} Chapter~\ref{ch:deep}.\\
\textbf{Goal.} Turn images into tensors, write one training loop and read its curves, compare a dense network and a CNN with Lab~4's classical baseline, look at what the CNN learned and where it fails, and save the weights with a model card.\\
\textbf{Scenario.} The sawmill from Lab~4 wants every defect its camera finds sorted into one of seven types, so that boards can be graded automatically. Lab~4's PCA and logistic regression got 63.3\% of the test images right. Is a neural network worth the extra machinery? Each step up the ladder has to earn its place on the same 3,134 test images, from boards no model has seen.\\
\textbf{Data.} \texttt{all\_datasets/\allowbreak unsupervised/\allowbreak wood\_surface\_defects/\allowbreak wood\_defects.npz}, the wood-defect images from Lab~4: 15,701 colour photos, $32\times32$ pixels, of seven defect types on sawn boards (Kodytek, Bodzas and Bilik, 2022).\\
\textbf{Notebook.} \texttt{all\_experiments/\allowbreak lab07\_deep\_learning\_cnn/\allowbreak lab07\_deep\_learning\_cnn\_worked.ipynb}, with a README beside it.\\
\textbf{Hand in.} The executed notebook, \texttt{results/lab07/}, the weights with their card and a short conclusion, as listed in the checklist at the end of this sheet.
\end{labproject}

\begin{labquestion}{4}{Write the training loop and train}
The training loop is the whole method. Each epoch shuffles the training images and walks through them in batches of 128. For each batch: compute the class scores (forward pass), compute the cross-entropy loss, compute every gradient with \texttt{backward()}, and let the optimizer move every weight a small step. After each epoch, accuracy is recorded on the training and validation images. \texttt{predict} works in chunks of 2,000, so scoring many images never needs them all in memory at once.
\end{labquestion}

\labpartopen{Part C}{A convolutional network}{Questions 6--10 \textbullet\ Data: wood surface defects}{Build a CNN, compare it with the dense network on the test images, and look at its mistakes and filters.}

\begin{labquestion}{6}{Build a CNN and trace its shapes}
A CNN keeps the image as a grid. The first layer slides sixteen $3\times3$ filters, each reading all three colours, across it and produces sixteen feature maps; max pooling halves each map; a second layer does the same with thirty-two filters; the result is flattened and classified by a small dense layer. Printing the shape after each stage shows where the numbers go.
\end{labquestion}
\begin{labanswer}
\input{labs/visuals/07-worked-case.tex}
\lstinputlisting[style=utppython,firstline=124,lastline=143]{all_experiments/lab07_deep_learning_cnn/lab07_deep_learning_cnn_worked.py}
\begin{refoutput}
\begin{lstlisting}[style=utpterminal]
trainable weights: 136679
Conv2d     -> (16, 32, 32)
MaxPool2d  -> (16, 16, 16)
Conv2d     -> (32, 16, 16)
MaxPool2d  -> (32, 8, 8)
Flatten    -> (2048,)
Linear     -> (64,)
Linear     -> (7,)
\end{lstlisting}
\end{refoutput}

\textbf{What it means.} Padding keeps each convolution at the same spatial size, and each pool halves it: 32, 16, 8. The two convolutions hold only 5,088 weights (448 and 4,640); the first \texttt{Linear} layer holds 131,136 of the 136,679. Its 2,048 inputs must match the flattened tensor, and that mismatch is the commonest bug when changing an architecture. The CNN has a third of the dense network's weights.
\end{labanswer}

\begin{expectedfindings}
\textbf{Warm-up.} $32\times32\times3=3{,}072$ numbers; $3{,}072\times128+128=393{,}344$ and $128\times7+7=903$, so 394,247 weights. The first block gives $16\times16\times16$, with $3\times16\times9+16=448$ weights; after the second, $32\times8\times8=2{,}048$ numbers reach a dense layer of $2{,}048\times64+64=131{,}136$ weights.
\begin{enumerate}
  \item About 0.45 (0.450 in the check script), against 0.557 with ReLU trained the same way, and 0.638 for Lab~4's logistic regression on all 3,072 pixels. Without an activation the two layers collapse into one linear map, so it is logistic regression with extra steps, and after only 10 epochs it has not even reached what Lab~4's fully trained version scored.
  \item Test accuracy is about 0.571, 0.686, 0.690 and 0.197. The smallest rate is simply slow: still climbing after 10 epochs. The largest makes the network call every image a live knot, so it scores the share of live knots among the test images, 19.7\%: the overshoot from the practice bowl of Chapter~\ref{ch:learning}.
  \item About 0.699 without dropout, against 0.686 with it in the same script, a difference of about one point. That is smaller than the 1.4 points between this script and the notebook for the very same CNN, so it is no difference you could defend. After 10 epochs training and validation are only about a point apart, so there is little overfitting for dropout to prevent; try it again on a longer run, once the curves start to part.
\end{enumerate}
\end{expectedfindings}

\begin{troubleshoot}
\begin{description}
  \item[\texttt{No module named 'torch'}] Compare the first line of the Setup output with the environment you installed into. Register the right environment as a kernel, and switch to it.
  \item[\texttt{OMP: Error \#15} on Windows] Two OpenMP runtimes are loaded. The Setup cell sets \texttt{KMP\_DUPLICATE\_LIB\_OK} before importing NumPy; restart the kernel so it takes effect.
  \item[\texttt{mat1 and mat2 shapes cannot be multiplied}] A \texttt{Linear} layer's input size does not match the flattened tensor. Print the shapes with the loop from Question~6.
  \item[\texttt{Invalid device id}] You set \texttt{CUDA\_VISIBLE\_DEVICES} to an empty string. Use \texttt{-1}.
  \item[Tensors on different devices] Use \texttt{.to(DEVICE)} for the model and data, and \texttt{.cpu()} before plotting.
  \item[An image looks scrambled when plotted] PyTorch keeps colour first, $3\times32\times32$; matplotlib wants it last. Use \texttt{.permute(1, 2, 0)} before \texttt{imshow}, as Question~2 does.
\end{description}
\end{troubleshoot}
