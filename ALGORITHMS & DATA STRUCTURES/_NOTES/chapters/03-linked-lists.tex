\chapter{Linked Lists I: Singly and Doubly Linked Lists}\label{ch:linked-lists}

\chapterguide%
  {Know how arrays store data contiguously and provide direct index access.}
  {explain nodes, head pointers, and address fields; compare arrays and linked lists; distinguish singly and doubly linked lists; and trace insertion, deletion, and traversal.}

A linked list is a linear data structure made of a sequence of \term{nodes}. Each node stores data and one or more addresses that connect it to adjacent nodes. Unlike an array, the nodes do not need to occupy one contiguous block of memory.

\section{The basic node model}

The Week III slides describe a node as having two conceptual parts: a data field and an address field. The address field stores where an adjacent node can be found.

The \term{head} identifies the first node. From the head, the remaining nodes are reached by repeatedly following the stored links.

\begin{keyidea}
An array answers ``where is item $i$?'' by index arithmetic. A linked list answers it by following a chain of pointers from the head.
\end{keyidea}

\section{Why use a linked list?}

The Week III slides give four advantages.

\section{Limitations of linked lists}

The slide deck also emphasizes three disadvantages:

\begin{itemize}
  \item \term{No random access.} Reaching a node normally starts from the head.
  \item \term{Search is slower than direct array access.} A sequential search takes $O(n)$ in the stated model.
  \item \term{Extra memory is required.} Every node stores one or more pointer fields.
\end{itemize}

\section{Singly linked lists}

A singly linked list node contains a data field and a \texttt{next} pointer. From a given node, the list can move forward to the next node, but there is no direct link back to the previous one.

\begin{lstlisting}
struct Node {
    int data;
    Node* next;
};
\end{lstlisting}

The slide deck names three basic operations: insertion, deletion, and traversal.

\subsection{Traversal}

\begin{lstlisting}
void display(Node* head) {
    Node* current = head;
    while (current != nullptr) {
        cout << current->data << ' ';
        current = current->next;
    }
    cout << '\n';
}
\end{lstlisting}

Every visited node advances the pointer one link. If the desired element is near the end, most of the list may need to be visited.

\subsection{Insert at the beginning}

\begin{mlsteps}
  \item Allocate a new node.
  \item Point the new node's \texttt{next} to the current head.
  \item Move \texttt{head} to the new node.
\end{mlsteps}

\begin{lstlisting}
void pushFront(Node*& head, int value) {
    Node* n = new Node{value, head};
    head = n;
}
\end{lstlisting}

\subsection{Delete by value}

The Week III lab asks for deletion by value. A singly linked list must preserve access to the previous node so its \texttt{next} link can bypass the deleted node.

\begin{lstlisting}
bool deleteValue(Node*& head, int value) {
    if (head == nullptr) return false;

    if (head->data == value) {
        Node* old = head;
        head = head->next;
        delete old;
        return true;
    }

    Node* current = head;
    while (current->next != nullptr &&
           current->next->data != value) {
        current = current->next;
    }

    if (current->next == nullptr) return false;

    Node* old = current->next;
    current->next = old->next;
    delete old;
    return true;
}
\end{lstlisting}

\section{Doubly linked lists}

A doubly linked list stores two links in every node: \texttt{prev} and \texttt{next}. This supports both forward and backward traversal.

\section{Singly vs doubly linked lists}

Feature & Singly linked list & Doubly linked list \\
\midrule

\section{Array vs linked list}

\begin{mltable}
\begin{tabularx}{\linewidth}{@{}>{\bfseries\leavevmode\color{ADSNavy}}p{0.20\linewidth}X X@{}}
\toprule
\rowcolor{ADSPaleBlue!92}
Feature & Array & Linked list \\
\midrule
Memory layout & Contiguous & Non-contiguous allowed \\
Size & Fixed for a raw array or resized manually & Dynamic through node allocation \\
Access & Direct using index & Sequential from head \\
Insertion/deletion & Can require shifting elements & Pointer updates can avoid shifting \\
Extra memory & No per-element pointer overhead & Pointer fields are stored in each node \\
\bottomrule
\end{tabularx}
\end{mltable}

\begin{pitfall}
``Insertion is easy in a linked list'' does not mean ``finding the insertion position is always fast.'' If the program must first search through $n$ nodes to locate the position, that search still costs traversal time.
\end{pitfall}

\begin{quickcheck}
Why can a doubly linked list move backward while a singly linked list cannot? If you already have a pointer to a middle node, which representation stores more information that can help with deletion?
\end{quickcheck}

\begin{chapterrecap}
\begin{itemize}
  \item A linked list is made of nodes connected by pointers.
  \item The first node is identified by the head pointer.
  \item Singly linked lists support forward traversal through \texttt{next}.
  \item Doubly linked lists add \texttt{prev} and can traverse in both directions.
  \item Linked lists are dynamic and flexible but require pointer memory and sequential access.
  \item Common operations are insertion, traversal, and deletion.
\end{itemize}
\end{chapterrecap}
