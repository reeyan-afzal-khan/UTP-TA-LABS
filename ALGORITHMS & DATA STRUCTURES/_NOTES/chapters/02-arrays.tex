An \term{array} stores a collection of similar data items of the same type. The Week II slides emphasize three properties: same-type elements, contiguous memory locations, and random access through index positions.

\begin{firstread}
Remember the sequence \textbf{Store $\rightarrow$ Access $\rightarrow$ Process}. Arrays make the access step simple because an index identifies the position directly.
\end{firstread}

\section{What is an array?}

Consider the one-dimensional array
\[
[12,\ 25,\ 18,\ 30,\ 22].
\]
Its indexes are $0,1,2,3,4$ in normal C++ indexing.

\subsection{Array properties from the slides}

\begin{itemize}
  \item Every element has the same data type and therefore the same element size.
  \item Elements are stored at contiguous memory locations.
  \item The first element occupies the smallest memory location in the block.
  \item An element can be accessed directly from its index because its address can be calculated from the base address and element size.
\end{itemize}

\section{Address calculation}

The slides state that the address of an array element can be calculated from the base address and element size. A standard expression for a one-dimensional, zero-based array is
\[
\operatorname{address}(A[i]) = \operatorname{base}(A) + i \times \operatorname{sizeof}(A[0]).
\]

\begin{workedexample}
If the base address is 1000 and each integer occupies 4 bytes, then the address of \texttt{A[3]} is
\[
1000 + 3(4) = 1012.
\]
This arithmetic is the reason direct index access does not require traversing the earlier elements.
\end{workedexample}

\begin{clarification}
The formula above is an explanatory expansion of the slide statement about base address and element size. The slides themselves do not provide a numeric address formula.
\end{clarification}

\section{One-dimensional vs two-dimensional arrays}

A 1D array forms a single indexed sequence. A 2D array stores values in rows and columns and is commonly used for tables, grids, and matrices.

In C++:

\begin{lstlisting}
int matrix[3][3] = {
    {1, 2, 3},
    {4, 5, 6},
    {7, 8, 9}
};

cout << matrix[1][2];   // 6
\end{lstlisting}

The first index chooses the row; the second chooses the column.

\section{Processing a 2D array with nested loops}

The Week II summary explicitly connects 2D arrays with nested loops.

\begin{lstlisting}
for (int r = 0; r < 3; ++r) {
    for (int c = 0; c < 3; ++c) {
        cout << matrix[r][c] << ' ';
    }
    cout << '\n';
}
\end{lstlisting}

The outer loop changes rows, while the inner loop visits the columns within the current row.

\begin{workedexample}
To compute the sum of every element in a $3\times3$ matrix, initialize \texttt{sum = 0}, visit each pair \texttt{[r][c]}, and add the value. The traversal touches each matrix cell once.
\end{workedexample}

\section{Why arrays are useful}

The Week II slides give three practical motivations:

\begin{itemize}
  \item multiple values can be stored under one variable name;
  \item multiple values can be processed quickly and systematically;
  \item searching and sorting operations can be applied naturally to the indexed sequence.
\end{itemize}

Arrays are especially useful when the number of elements is known and direct index access is important.

\section{Matrix multiplication as a lab-style problem}

The Week II material explicitly points to multi-dimensional array problems such as matrix multiplication. If $A$ is $m\times k$ and $B$ is $k\times n$, then the product $C$ is $m\times n$ with
\[
C[i][j] = \sum_{t=0}^{k-1} A[i][t]B[t][j].
\]

\begin{lstlisting}
for (int i = 0; i < m; ++i) {
    for (int j = 0; j < n; ++j) {
        C[i][j] = 0;
        for (int t = 0; t < k; ++t) {
            C[i][j] += A[i][t] * B[t][j];
        }
    }
}
\end{lstlisting}

\begin{clarification}
The matrix-multiplication formula and loop structure are an implementation expansion of the Week II lab prompt, which asks for multidimensional-array problems such as matrix multiplication but does not spell out the algorithm.
\end{clarification}

\begin{pitfall}
Do not confuse an index with the stored value. In the array \texttt{[12,25,18,30,22]}, index 3 is the position and 30 is the value at that position.
\end{pitfall}

\begin{quickcheck}
For a $4\times5$ integer matrix, what do the two indexes in \texttt{A[2][4]} represent? Why can a raw array element be accessed directly without walking through earlier elements?
\end{quickcheck}

\begin{chapterrecap}
\begin{itemize}
  \item Arrays store same-type elements in contiguous memory.
  \item Indexing gives direct access to an element.
  \item Address calculation depends on base address, index, and element size.
  \item 2D arrays represent rows and columns.
  \item Nested loops are the standard course pattern for matrix-style processing.
  \item Multidimensional arrays support practical tasks such as matrix multiplication.
\end{itemize}
\end{chapterrecap}
