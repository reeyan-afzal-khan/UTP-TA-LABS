A \term{stack} is an abstract data type in which access occurs at one end called the \term{top}. The defining rule is \term{LIFO}: Last In, First Out.

\section{The LIFO principle}

If 10 is inserted first, then 20, then 30, the top is 30. Removing an item removes 30 before 20 or 10.

The slide deck names the main operations:

\begin{description}[leftmargin=1.2in,style=nextline]
  \item[push()] Insert a new item at the top.
  \item[pop()] Remove the top item.
  \item[peek()] Read the top item without removing it.
  \item[isEmpty()] Check whether there is no item to access.
  \item[isFull()] Check capacity for a fixed-size representation.
  \item[display()] Show the stored items.
\end{description}

\section{Stack states: overflow and underflow}

The learning outcomes explicitly ask students to identify both conditions.

\begin{description}[leftmargin=1.35in,style=nextline]
  \item[Overflow] A push is attempted on a fixed-size stack that has no free slot.
  \item[Underflow] A pop or peek is attempted on an empty stack.
\end{description}

\begin{pitfall}
Always test the relevant state before changing the top index or dereferencing the top node. Underflow bugs often become invalid memory access.
\end{pitfall}

\section{Array-based stack}

The slides specifically frame the array implementation as fixed-size.

\begin{lstlisting}
class ArrayStack {
private:
    static const int CAPACITY = 5;
    int data[CAPACITY];
    int topIndex = -1;

public:
    bool isEmpty() const { return topIndex == -1; }
    bool isFull()  const { return topIndex == CAPACITY - 1; }

    bool push(int value) {
        if (isFull()) return false;
        data[++topIndex] = value;
        return true;
    }

    bool pop(int& removed) {
        if (isEmpty()) return false;
        removed = data[topIndex--];
        return true;
    }

    bool peek(int& value) const {
        if (isEmpty()) return false;
        value = data[topIndex];
        return true;
    }
};
\end{lstlisting}

The top index is enough to identify the active end of the structure. In the normal implementation above, push, pop, and peek do not scan the existing elements.

\section{Linked-list stack}

A linked-list stack uses the head node as the top. Pushing inserts at the head; popping removes the head.

\begin{lstlisting}
struct StackNode {
    int data;
    StackNode* next;
};

class LinkedStack {
private:
    StackNode* top = nullptr;

public:
    bool isEmpty() const { return top == nullptr; }

    void push(int value) {
        top = new StackNode{value, top};
    }

    bool pop(int& removed) {
        if (isEmpty()) return false;
        StackNode* old = top;
        removed = old->data;
        top = top->next;
        delete old;
        return true;
    }

    bool peek(int& value) const {
        if (isEmpty()) return false;
        value = top->data;
        return true;
    }
};
\end{lstlisting}

\begin{clarification}
The Week V lab lists \texttt{isFull()} for both array and linked-list stacks. A linked-list stack normally has no predetermined fixed capacity; it is ``full'' only if an external capacity rule is imposed or memory allocation fails. This distinction is not stated on the slide, so the notes preserve the lab operation while making the implementation assumption explicit.
\end{clarification}

\begin{intuition}
A physical stack of plates behaves like the ADT: adding a plate changes only the top, and removing a plate takes the most recently added plate first.
\end{intuition}

The same discipline runs underneath every C++ program. Each function call pushes a frame
holding that call's parameters and local variables; each \texttt{return} pops one
(\figref{fig:call-stack}). This is why a runaway recursion produces a \emph{stack overflow},
and why the recursive tree traversals in \chapref{ch:trees-i} return to the correct parent
without storing one explicitly.

\section{Lab-manual application: infix to postfix}

The official lab manual adds one stack problem that is not spelled out in the Week V slide deck: \term{conversion of an infix expression to postfix using a stack}. The stack temporarily stores operators while operands are sent directly to the output.

For example, the infix expression
\[
A + B * C
\]
becomes
\[
A\;B\;C\;*\;+.
\]
Multiplication is emitted before addition because it has higher precedence.

\begin{mlsteps}
  \item Read the expression from left to right.
  \item Send operands directly to the postfix output.
  \item Push an opening parenthesis onto the operator stack.
  \item For an operator, pop operators of higher precedence (and, for left-associative operators, equal precedence) before pushing the new operator.
  \item On a closing parenthesis, pop until the matching opening parenthesis is removed.
  \item At the end, pop all remaining operators.
\end{mlsteps}

\begin{clarification}
The lab manual names infix-to-postfix conversion as practice but does not provide the precedence/associativity algorithm in the supplied material. The procedure above is standard supporting context so the named lab task can be implemented.
\end{clarification}

\figref{fig:infix-trace} traces the whole conversion for a slightly larger expression. Read
it as a table of states: the stack column is the operator stack from bottom to top, and the
output column only ever grows.

\end{quickcheck}

\begin{chapterrecap}
\begin{itemize}
  \item A stack is an ADT with access at the top.
  \item LIFO means the most recently inserted item is removed first.
  \item \texttt{push()} inserts, \texttt{pop()} removes, and \texttt{peek()} reads the top.
  \item Fixed-size stacks can overflow; empty stacks can underflow.
  \item Stacks can be implemented with arrays or linked lists.
\end{itemize}
\end{chapterrecap}
