! ============================================================
! Lab 4 --- R3 single-area OSPF (LAN 3 gateway)
! Same topology as Lab 3. REMOVE the static routes first.
! ============================================================

system-view

! ---------- Remove Lab 3 statics ----------
undo ip route-static 192.168.1.0 24 10.0.23.2
undo ip route-static 192.168.1.0 24 10.0.13.1

! ---------- OSPF ----------
ospf 1 router-id 3.3.3.3
 area 0
  network 192.168.3.0 0.0.0.255
  network 10.0.23.0 0.0.0.3
  network 10.0.13.0 0.0.0.3
 quit
quit
save

! ---------- Verify ----------
! display ospf peer brief
!   Two neighbours (R2 and R1), both Full.
!
! ---------- The point of this lab, in one comparison ----------
! In Lab 3 you typed a route on R1 AND a mirror route on R3, then a
! backup pair on top of that, and a ping only worked once every one of
! them was present. Here each router was told which of its OWN
! interfaces participate, and the reachability fell out.
!
! Both failover paths exist automatically too: OSPF already knows the
! 10.0.13.0/30 link and will use it when the primary drops --- no
! preference values, no second set of statements.
!
! Cost check:
!   display ip routing-table protocol ospf
!   Huawei derives cost from interface bandwidth, so the two-hop path
!   through R2 and the one-hop backup may not cost what you expect.
!   Confirm which path is active BEFORE the failover test, or you will
!   misread the result.
