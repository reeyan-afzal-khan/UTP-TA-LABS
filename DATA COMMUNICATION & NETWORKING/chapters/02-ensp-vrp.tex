\section{Which device to drag}
The labs name interfaces such as \cmd{GigabitEthernet0/0/0} and
\cmd{Serial1/0/0} without saying which eNSP model provides them. These
are the models the exercises assume.

\begin{center}
\begin{tabularx}{\linewidth}{>{\bfseries}p{0.15\linewidth}p{0.17\linewidth}p{0.24\linewidth}X}
\toprule
Palette item & Model & Interfaces you get & Used in\\\midrule
Router & AR2220 & 3 $\times$ GE, no serial by default & Labs 2--6, 9\\
Switch & S5700 & 24 $\times$ GE & Labs 7--8\\
Switch & S3700 & 24 $\times$ FE & where 100\,Mbit/s is wanted\\
End device & PC & one Ethernet interface & Labs 2, 6, 8\\
End device & Server & one Ethernet interface & FTP and DHCP work\\\bottomrule
\end{tabularx}
\end{center}

\begin{pitfall}
The AR2220 ships with \emph{no serial interfaces}. Lab~\ref{ch:wan} calls
for \cmd{Serial1/0/0}, so before starting that topology you must
right-click each router, open \textbf{Settings}, and drag a \textbf{2SA}
module into an empty slot. The device has to be powered off to accept it.
Skipping this produces \cmd{Error: Wrong parameter found at '\^{}' position}
on the very first \cmd{interface Serial 1/0/0}, which reads like a typing
mistake and is not one.
\end{pitfall}

\subsection{Picking the right cable}
The connection palette offers several cable types. Two of them cover
everything in this book.

\begin{center}
\begin{tabularx}{\linewidth}{>{\bfseries}p{0.17\linewidth}p{0.26\linewidth}X}
\toprule
Cable & Join & Note\\\midrule
Auto & anything to anything & eNSP picks the correct type; use it unless the lab says otherwise.\\
Copper & Ethernet to Ethernet & The explicit form of the same thing.\\
Serial & Serial to Serial & Lab~\ref{ch:wan} only. The end you draw \emph{from} becomes the DCE.\\\bottomrule
\end{tabularx}
\end{center}

\begin{keyidea}
A red dot on an interface means the link is down; green means up. After
pressing start, wait for both ends to turn green before opening a console.
Half the ``the command did not work'' reports in these labs are a console
opened on a device that had not finished booting.
\end{keyidea}

\section{The topology-building loop}
\begin{netsteps}
\item Drag the required hosts, routers, and switches onto the canvas.
\item Connect the specified interfaces with the correct medium.
\item Configure addresses through host settings or device consoles.
\item Start the devices and wait for them to finish booting.
\item Start Wireshark on the interface to be monitored.
\item Generate traffic, such as \cmd{ping <IP-address>}, and inspect it.
\end{netsteps}

\begin{keyidea}
Use this cycle throughout the course: \textbf{build $\rightarrow$ configure $\rightarrow$ inspect $\rightarrow$ test $\rightarrow$ save}.
\end{keyidea}

\section{Huawei VRP views}
VRP commands are organized into hierarchical views; the prompt identifies the active view.

\begin{tabularx}{\linewidth}{p{0.40\linewidth}X}
\toprule
Prompt pattern & Meaning\\\midrule
\cmd{<Huawei>} & User view; commonly used for display, ping, save, and entry into system view.\\
\cmd{[Huawei]} or \cmd{[R1]} & System view; used for device-wide configuration and entry into protocol/interface views.\\
\cmd{[R1-GigabitEthernet0/0/0]} & Interface view; commands affect the selected interface.\\
\cmd{[R1-ospf-1]} & Protocol/process view; commands affect the selected routing process.\\\bottomrule
\end{tabularx}

The table says which view you are in. The diagram says how to get to the
next one, which is the part that trips people up: \cmd{quit} goes up one
level, \cmd{return} goes all the way to user view.

\begin{pitfall}
A command rejected as unrecognised is usually a command typed in the
wrong view rather than a command that does not exist. \cmd{ip
route-static} only works in system view; \cmd{ip address} only works in
interface view. Read the prompt before re-typing.
\end{pitfall}

\section{Direct-link practice}
R1 and R3 share \cmd{10.0.13.0/24}, using \cmd{10.0.13.1} and \cmd{10.0.13.3}, respectively.

\sourceimage[0.82\linewidth]{Directly connected R1--R3 topology from the supplied Lab 2B slide}{vrp-direct-link-topology.png}

\subsection{Configure R1}
\begin{lstlisting}[style=dcnterminal]
<Huawei> system-view
[Huawei] sysname R1
[R1] interface GigabitEthernet 0/0/0
[R1-GigabitEthernet0/0/0] ip address 10.0.13.1 24
[R1-GigabitEthernet0/0/0] description This interface connects to R3-G0/0/0
\end{lstlisting}

\subsection{Configure R3}
\begin{lstlisting}[style=dcnterminal]
<Huawei> system-view
[Huawei] sysname R3
[R3] interface GigabitEthernet 0/0/0
[R3-GigabitEthernet0/0/0] ip address 10.0.13.3 255.255.255.0
[R3-GigabitEthernet0/0/0] description This interface connects to R1-G0/0/0
\end{lstlisting}

The prefix \cmd{24} and mask \cmd{255.255.255.0} are equivalent.

\section{Verification commands}
The single most useful command after addressing anything is
\cmd{display ip interface brief}: it lists every interface, its address,
and both state columns on one screen.

\begin{vrpbox}{<R1> display ip interface brief}
\begin{lstlisting}[style=dcnvrp]
*down: administratively down
^down: standby
(l): loopback
(s): spoofing
The number of interface that is UP in Physical is 2
The number of interface that is DOWN in Physical is 1
The number of interface that is UP in Protocol is 2
The number of interface that is DOWN in Protocol is 1

Interface                   IP Address/Mask    (*\hi{Physical}*)  (*\hi{Protocol}*)
GigabitEthernet0/0/0        10.0.13.1/24       (*\higreen{up}*)        (*\higreen{up}*)
GigabitEthernet0/0/1        unassigned         (*\hired{down}*)      (*\hired{down}*)
NULL0                       unassigned         up        up(s)
\end{lstlisting}
\end{vrpbox}
\vrpread{the two state columns fail for different reasons. \cmd{Physical
down} is a cabling or shutdown problem. \cmd{Physical up} with
\cmd{Protocol down} means the wire is fine and the agreement across it is
not --- an encapsulation or authentication mismatch, which is exactly the
fault Lab~\ref{ch:wan} produces on purpose.}


\begin{commandmap}
\begin{tabularx}{\linewidth}{>{\ttfamily}p{0.38\linewidth}X}
\toprule
Command & Evidence\\\midrule
 display this & Configuration in the current view.\\
 display interface GigabitEthernet 0/0/0 & Detailed state, address, description, MTU, and counters.\\
 display ip interface brief & Interface addresses and physical/protocol states.\\
 ping 10.0.13.3 & Layer-3 reachability from R1 to R3.\\
 save & Store the current configuration.\\
 display saved-configuration & Stored configuration.\\\bottomrule
\end{tabularx}
\end{commandmap}

\begin{verification}
A healthy direct link has compatible addresses and reports both physical and protocol status as \textbf{up}. Verify it with ping, then save the configuration.
\end{verification}

\begin{pitfall}
A failed ping is only a symptom. Check interface state first: physical down indicates a link problem; physical up/protocol down points to configuration or peer state. Investigate routing only after the direct link is healthy.
\end{pitfall}
