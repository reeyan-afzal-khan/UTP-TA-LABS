\section{Why aggregate Ethernet links?}
Link aggregation combines physical Ethernet links into one logical connection. LACP coordinates membership and reacts to member failure or recovery.

\sourceimage[0.86\linewidth]{Link aggregation between a switch and a server}{lacp-switch-server.png}

\compactsourceimage[0.82\linewidth]{Two physical links presented as one logical link between switches}{lacp-switch-switch.png}

\begin{keyidea}
An Eth-Trunk is the logical bundle; its physical interfaces are members. LACP coordinates the active set between peers.
\end{keyidea}

\section{Lab topology}
S1 and S2 are connected using two member links, \cmd{G0/0/9} and \cmd{G0/0/10}. The bundle is represented as \cmd{Eth-Trunk 1}.

\sourceimage[0.76\linewidth]{Ethernet link-aggregation topology from the supplied Lab 7 slide}{lacp-topology.png}

\section{Prepare the physical interfaces}
The exercise disables auto-negotiation and sets both member links to 100 Mbit/s on each switch.
\begin{lstlisting}[style=dcnterminal]
[S1] interface GigabitEthernet 0/0/9
[S1-GigabitEthernet0/0/9] undo negotiation auto
[S1-GigabitEthernet0/0/9] speed 100
[S1] interface GigabitEthernet 0/0/10
[S1-GigabitEthernet0/0/10] undo negotiation auto
[S1-GigabitEthernet0/0/10] speed 100
\end{lstlisting}
Configure S2 identically, then verify both interfaces with \cmd{display interface}.

\section{Manual link aggregation}
First create Eth-Trunk 1 and add both interfaces manually.
\begin{lstlisting}[style=dcnterminal]
[S1] interface Eth-Trunk 1
[S1-Eth-Trunk1] quit
[S1] interface GigabitEthernet 0/0/9
[S1-GigabitEthernet0/0/9] eth-trunk 1
[S1] interface GigabitEthernet 0/0/10
[S1-GigabitEthernet0/0/10] eth-trunk 1
\end{lstlisting}
Repeat on S2.

\section{Rebuild the bundle in static LACP mode}
Remove the manual memberships with \cmd{undo eth-trunk}, then rebuild the trunk in LACP mode.
\begin{lstlisting}[style=dcnterminal]
[S1] interface Eth-Trunk 1
[S1-Eth-Trunk1] mode lacp
[S1] interface GigabitEthernet 0/0/9
[S1-GigabitEthernet0/0/9] eth-trunk 1
[S1] interface GigabitEthernet 0/0/10
[S1-GigabitEthernet0/0/10] eth-trunk 1
\end{lstlisting}
Repeat on S2.

\section{Manipulate LACP priorities}
Set S1's system and member-interface priorities to 100.
\begin{lstlisting}[style=dcnterminal]
[S1] lacp priority 100
[S1] interface GigabitEthernet 0/0/9
[S1-GigabitEthernet0/0/9] lacp priority 100
[S1] interface GigabitEthernet 0/0/10
[S1-GigabitEthernet0/0/10] lacp priority 100
\end{lstlisting}

\begin{conceptmap}
\textbf{Physical preparation} $\rightarrow$ compatible member links\\
$\downarrow$\\
\textbf{Eth-Trunk membership} $\rightarrow$ one logical bundle\\
$\downarrow$\\
\textbf{Static LACP mode} $\rightarrow$ protocol-coordinated active members\\
$\downarrow$\\
\textbf{Priority settings} $\rightarrow$ influence selection behavior.
\end{conceptmap}

\section{Troubleshooting order}
\begin{netsteps}
\item Confirm the physical interfaces are up and use compatible speed/negotiation settings.
\item Confirm the same member links are assigned to Eth-Trunk 1 on both switches.
\item Confirm both sides use the same aggregation mode.
\item Inspect LACP system/interface priorities if active-link selection is not what the lab expects.
\item Use Eth-Trunk display output rather than checking only individual interfaces.
\end{netsteps}

\begin{pitfall}
A physical link may be up but excluded from the bundle when membership or LACP mode differs across peers. Verify the logical trunk on both ends.
\end{pitfall}
