\section{The topology: three routers and three transit networks}
Three routers form a triangle, and each has a loopback network. Routers learn directly connected networks automatically; remote networks require a route.

\section{Why the first remote ping fails}
After addressing, each router can reach its direct neighbors. R2 cannot reach R3's loopback \cmd{10.0.3.0/24} until its routing table identifies a path.

\vrpread{every \cmd{Proto} is \cmd{Direct}. R2 knows only the networks
attached to its own interfaces. \cmd{10.0.3.0/24} and \cmd{10.0.13.0/24}
appear nowhere, so a ping to R3's loopback has nothing to match.}

\begin{pitfall}
Three entries appear per connected network, not one: the network itself
(\cmd{/24}), the router's own address as a host route (\cmd{/32}), and the
broadcast address. Only the first is a forwarding path. Reading
\cmd{Destinations : 13} as ``thirteen reachable networks'' is what makes a
correct table look wrong.
\end{pitfall}

\begin{keyidea}
A router matches the destination IP against its routing table. Without a matching route, it cannot forward the packet.
\end{keyidea}

\subsection{How the match is chosen}
Several entries can match one destination. The router does not take the
first, or the cheapest: it takes the one with the longest prefix, which
means the most specific. Preference only breaks ties between routes of
\emph{equal} prefix length.

\section{Static-route syntax in this lab}
The source demonstrates next-hop static routes in the form:
\begin{center}
\cmd{ip route-static <destination-network> <mask/prefix> <next-hop> [preference <value>]}
\end{center}
A static route says: \emph{send this destination network to this next hop}.

\section{Primary routes on R2}
The lab directs R2 toward R3 by using next hop \cmd{10.0.23.3}.
\begin{lstlisting}[style=dcnterminal]
[R2] ip route-static 10.0.13.0 24 10.0.23.3
[R2] ip route-static 10.0.3.0 24 10.0.23.3
<R2> display ip routing-table
\end{lstlisting}
On the lab's VRP image, a static route has default preference 60, so the primary route needs no explicit value.

\begin{workedexample}
R2 matches \cmd{10.0.3.3} to \cmd{10.0.3.0/24} and forwards it to \cmd{10.0.23.3}. R3 delivers it locally; the reply still needs a return route.
\end{workedexample}

\section{Backup static routes and route preference}
The alternate path through R1 uses a higher, less-preferred value, so it remains a backup.
\begin{lstlisting}[style=dcnterminal]
[R2] ip route-static 10.0.13.0 255.255.255.0 10.0.12.1 preference 80
[R2] ip route-static 10.0.3.0 24 10.0.12.1 preference 80
\end{lstlisting}
The route through R3 (preference 60) wins over the backup through R1 (80) until the primary path fails.

\begin{keyidea}
Preference decides which \emph{protocol} to believe when two of them
offer a route to the same prefix. It is compared only after longest-prefix
match has already narrowed the field, which is why a \cmd{/24} static
route still beats a \cmd{/8} OSPF route despite the worse preference.
\end{keyidea}

\begin{pitfall}
Failover is not instant. The router must first decide the next hop is unreachable, and only then install the backup. Expect to lose several pings during the switch --- that gap is the cost of detection, and it is why fast-converging protocols like OSPF (Chapter~\ref{ch:ospf}) exist.
\end{pitfall}

\begin{pitfall}
One supplied slide shows \cmd{255.255.25.0} while explaining a /24 mask. Elsewhere the same lab consistently uses /24, whose decimal form is \cmd{255.255.255.0}. The notes follow the lab's /24 objective and flag the source typo rather than treating it as a new subnet mask.
\end{pitfall}

\section{Verification sequence}
\begin{netsteps}
\item Use \cmd{display ip interface brief} to confirm all expected interfaces and addresses.
\item Ping directly connected neighbors first; a remote-routing test is meaningless if the local link is broken.
\item Use \cmd{display ip routing-table} and confirm that the intended static destination networks are present.
\item Ping the remote interface or loopback address.
\item For the backup-route portion, make the primary path unavailable as directed in the lab and confirm the alternate route becomes effective.
\end{netsteps}

\begin{verification}
Use both routing-table and ping evidence: one proves the route is installed; the other proves forwarding works.
\end{verification}

\begin{quickcheck}
\begin{enumerate}
\item Why can R2 reach a directly connected network without a static route?
\item What information does the next-hop address provide?
\item Why is the backup route configured with a preference value of 80 rather than 60?
\item Which command proves that the route exists before you test it with ping?
\end{enumerate}
\end{quickcheck}

\begin{chapterrecap}
Static routes map destinations to next hops. Verify direct links, add routes in both directions, inspect the table, and test traffic. A higher preference value can provide a backup path.
\end{chapterrecap}
