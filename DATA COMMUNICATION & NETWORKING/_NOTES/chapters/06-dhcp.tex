\section{What DHCP automates}
The supplied overview defines Dynamic Host Configuration Protocol (DHCP) as a client/server protocol that automatically provides a host with an IP address and related configuration such as a subnet mask and default gateway. The source highlights two benefits: \textbf{reliable IP address configuration} and \textbf{reduced network administration}.

\section{The detailed lab topology}
The implementation lab uses R1 and R3 as DHCP servers and S1/S2 as access-layer clients. It deliberately exercises two allocation methods: a named global pool and an interface-based pool.

\section{Step 1: prepare interfaces and isolate the intended path}
The detailed lab first configures the addressing and shuts selected interfaces so that only the intended DHCP path is active. It also disables several unused switch ports to prevent other devices or links from interfering with the experiment. The important lesson is methodological: \emph{control the topology before testing dynamic allocation}.

\section{Step 2: enable DHCP globally on the routers}
The source states that DHCP is not enabled by default.
\begin{lstlisting}[style=dcnterminal]
[R1] dhcp enable
[R3] dhcp enable
\end{lstlisting}

\section{Step 3: create the global address pools}
R1 creates \cmd{pool1} for \cmd{10.0.12.0/24}; R3 creates \cmd{pool2} for \cmd{10.0.23.0/24}. Both examples use a lease of 1 day and 12 hours.

\begin{lstlisting}[style=dcnterminal]
[R1] ip pool pool1
[R1-ip-pool-pool1] network 10.0.12.0 mask 24
[R1-ip-pool-pool1] gateway-list 10.0.12.1
[R1-ip-pool-pool1] lease day 1 hour 12
[R1] interface GigabitEthernet 0/0/1
[R1-GigabitEthernet0/0/1] dhcp select global

[R3] ip pool pool2
[R3-ip-pool-pool2] network 10.0.23.0 mask 24
[R3-ip-pool-pool2] gateway-list 10.0.23.3
[R3-ip-pool-pool2] lease day 1 hour 12
[R3] interface GigabitEthernet 0/0/2
[R3-GigabitEthernet0/0/2] dhcp select global
\end{lstlisting}

\section{Step 4: make the switches DHCP clients}
The management interface requests an address dynamically.
\begin{lstlisting}[style=dcnterminal]
[S1] dhcp enable
[S1] interface Vlanif 1
[S1-Vlanif1] ip address dhcp-alloc
<S1> display ip interface brief
\end{lstlisting}
The source performs the equivalent operation on S2. It then verifies the allocation from the corresponding router pool.

\section{Step 5: build interface-based address pools}
The second part of the lab changes which router interfaces are active and then configures DHCP directly under those interfaces.
\begin{lstlisting}[style=dcnterminal]
[R1] interface GigabitEthernet 0/0/2
[R1-GigabitEthernet0/0/2] dhcp select interface
[R1-GigabitEthernet0/0/2] dhcp server dns-list 10.0.23.254
[R1-GigabitEthernet0/0/2] dhcp server excluded-ip-address 10.0.23.254
[R1-GigabitEthernet0/0/2] dhcp server lease day 1 hour 12

[R3] interface GigabitEthernet 0/0/1
[R3-GigabitEthernet0/0/1] dhcp select interface
[R3-GigabitEthernet0/0/1] dhcp server dns-list 10.0.12.254
[R3-GigabitEthernet0/0/1] dhcp server excluded-ip-address 10.0.12.254
[R3-GigabitEthernet0/0/1] dhcp server lease day 1 hour 12
\end{lstlisting}

\begin{keyidea}
The \cmd{excluded-ip-address} command protects a specific address from dynamic assignment. In the lab, the same address is also configured as the DNS server value for clients, so excluding it prevents the DHCP allocator from handing that address to an ordinary client.
\end{keyidea}

\section{Step 6: force a fresh client request}
The source flushes the existing Vlanif1 state by shutting and re-enabling it, then activates the appropriate router interface. This forces the switch to request a new address from the interface-based pool.
\begin{lstlisting}[style=dcnterminal]
[S2] interface Vlanif 1
[S2-Vlanif1] shutdown
[S2-Vlanif1] undo shutdown

[R1] interface GigabitEthernet 0/0/2
[R1-GigabitEthernet0/0/2] undo shutdown
\end{lstlisting}
The lab repeats the process for S1 and R3 on the other subnet.

\begin{verifybox}
Do not treat ``DHCP enabled'' as success. The real evidence is: a client Vlanif receives an address, the address belongs to the expected subnet/pool, and the router's pool statistics show a used lease.
\end{verifybox}

\section{Troubleshooting DHCP}
\begin{netsteps}
\item Confirm the server-side routed interface is up and has the intended subnet address.
\item Confirm \cmd{dhcp enable} is present on the router.
\item For a global pool, verify the pool network/gateway and \cmd{dhcp select global} on the correct interface.
\item For an interface pool, verify \cmd{dhcp select interface} plus any excluded/DNS/lease settings.
\item Confirm the client has DHCP enabled and uses \cmd{ip address dhcp-alloc} on Vlanif1.
\item Cycle the client interface if the exercise requires a new lease, then inspect the client and pool state again.
\end{netsteps}

\begin{chapterrecap}
DHCP converts manual host addressing into a controlled allocation service. The lab practices both named global pools and interface-based pools, then verifies the result from both sides: the client shows a dynamically assigned address and the server pool shows that a lease is in use.
\end{chapterrecap}
