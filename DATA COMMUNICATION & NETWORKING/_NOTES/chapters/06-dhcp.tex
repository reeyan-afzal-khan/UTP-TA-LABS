\chapter{DHCP Address Allocation}\label{ch:dhcp}
\chapterguide{Router and switch interface configuration, IPv4 subnetting, and basic reachability.}{Explain DHCP's purpose, enable DHCP, build global and interface-based pools, configure switches to request addresses, reserve/exclude addresses, set leases and DNS information, and verify allocation state.}

\section{What DHCP automates}
Dynamic Host Configuration Protocol (DHCP) assigns clients an IP address and options such as a subnet mask, gateway, and DNS server. It improves consistency and reduces manual administration.

\subsection{The four-message exchange}
A client with no address cannot yet be addressed, so the conversation begins as a broadcast. The four steps are remembered as \term{DORA}.

\begin{netfigure}{DORA --- how a client with no address gets one}
\begin{tikzpicture}[node distance=1.0cm,
  msg/.style={-{Stealth[length=2.2mm]},thick},
  ml/.style={font=\scriptsize\color{MLInk},inner sep=1.5pt}]
\node[host] (c) {Client};
\node[router,right=6.4cm of c] (s) {Server};
\draw[draw=MLMuted,dashed] (c) -- ++(0,-4.0);
\draw[draw=MLMuted,dashed] (s) -- ++(0,-4.0);

\draw[msg,draw=MLOrange] ($(c)+(0,-0.75)$) -- node[ml,above]{\textbf{D}iscover \ \tiny broadcast: ``anyone there?''} ($(s)+(0,-0.75)$);
\draw[msg,draw=MLBlue]   ($(s)+(0,-1.65)$) -- node[ml,above]{\textbf{O}ffer \ \tiny ``you may have 10.0.12.20''} ($(c)+(0,-1.65)$);
\draw[msg,draw=MLOrange] ($(c)+(0,-2.55)$) -- node[ml,above]{\textbf{R}equest \ \tiny broadcast: ``I accept that one''} ($(s)+(0,-2.55)$);
\draw[msg,draw=MLGreen]  ($(s)+(0,-3.45)$) -- node[ml,above]{\textbf{A}cknowledge \ \tiny lease confirmed, clock starts} ($(c)+(0,-3.45)$);
\end{tikzpicture}

\smallskip
{\scriptsize The \textbf{Request} is broadcast, not sent directly to the chosen
server. That is deliberate: if two servers made offers, the broadcast tells
the one that was \emph{not} chosen to release the address it had reserved.}
\end{netfigure}

\begin{keyidea}
Discover and Request are broadcasts. Routers do not forward broadcasts, so a client and its DHCP server must share a broadcast domain --- or something must carry the request across. That ``something'' is the relay, in Section~\ref{sec:dhcp-relay}.
\end{keyidea}

\section{Step 1: prepare interfaces and isolate the intended path}
Configure addressing and disable unused paths before testing, so only the intended DHCP server can respond.

\section{Step 2: enable DHCP globally on the routers}
Enable DHCP globally before configuring pools.
\begin{lstlisting}[style=dcnterminal]
[R1] dhcp enable
[R3] dhcp enable
\end{lstlisting}

\section{Step 3: create the global address pools}
R1 creates \cmd{pool1} for \cmd{10.0.12.0/24}; R3 creates \cmd{pool2} for \cmd{10.0.23.0/24}. Each lease lasts 1 day and 12 hours.

\begin{lstlisting}[style=dcnterminal]
[R1] ip pool pool1
[R1-ip-pool-pool1] network 10.0.12.0 mask 24
[R1-ip-pool-pool1] gateway-list 10.0.12.1
[R1-ip-pool-pool1] lease day 1 hour 12
[R1] interface GigabitEthernet 0/0/1
[R1-GigabitEthernet0/0/1] dhcp select global

[R3] ip pool pool2
[R3-ip-pool-pool2] network 10.0.23.0 mask 24
[R3-ip-pool-pool2] gateway-list 10.0.23.3
[R3-ip-pool-pool2] lease day 1 hour 12
[R3] interface GigabitEthernet 0/0/2
[R3-GigabitEthernet0/0/2] dhcp select global
\end{lstlisting}

\section{Step 4: make the switches DHCP clients}
Configure the management interface as a DHCP client.
\begin{lstlisting}[style=dcnterminal]
[S1] dhcp enable
[S1] interface Vlanif 1
[S1-Vlanif1] ip address dhcp-alloc
<S1> display ip interface brief
\end{lstlisting}
Repeat on S2, then inspect the corresponding server pool.

\begin{commandmap}
\begin{tabularx}{\linewidth}{>{\ttfamily}p{0.42\linewidth}X}
\toprule
Command & What it proves\\\midrule
 display ip pool name pool1 & R1 pool settings and allocation counters.\\
 display ip pool name pool2 & R3 pool settings and allocation counters.\\
 display ip interface brief & Address and state of the switch Vlanif1.\\\bottomrule
\end{tabularx}
\end{commandmap}

\section{Step 5: build interface-based address pools}
Next, configure DHCP directly under the active routed interfaces.
\begin{lstlisting}[style=dcnterminal]
[R1] interface GigabitEthernet 0/0/2
[R1-GigabitEthernet0/0/2] dhcp select interface
[R1-GigabitEthernet0/0/2] dhcp server dns-list 10.0.23.254
[R1-GigabitEthernet0/0/2] dhcp server excluded-ip-address 10.0.23.254
[R1-GigabitEthernet0/0/2] dhcp server lease day 1 hour 12

[R3] interface GigabitEthernet 0/0/1
[R3-GigabitEthernet0/0/1] dhcp select interface
[R3-GigabitEthernet0/0/1] dhcp server dns-list 10.0.12.254
[R3-GigabitEthernet0/0/1] dhcp server excluded-ip-address 10.0.12.254
[R3-GigabitEthernet0/0/1] dhcp server lease day 1 hour 12
\end{lstlisting}

\begin{keyidea}
\cmd{excluded-ip-address} prevents the DNS server address from being leased to a client.
\end{keyidea}

\section{Step 6: force a fresh client request}
Cycle Vlanif1 to force a fresh request from the interface-based pool.
\begin{lstlisting}[style=dcnterminal]
[S2] interface Vlanif 1
[S2-Vlanif1] shutdown
[S2-Vlanif1] undo shutdown

[R1] interface GigabitEthernet 0/0/2
[R1-GigabitEthernet0/0/2] undo shutdown
\end{lstlisting}
Repeat for S1 and R3 on the other subnet.

\begin{verification}
Success requires a client address from the expected subnet and a matching used lease in the server pool.
\end{verification}

\section{DHCP relay: reaching a server on another segment}\label{sec:dhcp-relay}

Everything above assumes the client and the server share a segment. Real networks centralise the DHCP server, so the client's broadcast has to cross a router that, by design, will not forward it.

A \term{relay agent} solves this by translating the conversation. The router receives the broadcast on the client side, rewrites it as a \emph{unicast} to the configured server, and inserts the receiving interface's address so the server knows which pool to allocate from.

\begin{netfigure}{The relay converts a broadcast into a unicast, and back}
\begin{tikzpicture}[node distance=1.0cm and 2.1cm,
  ml/.style={font=\scriptsize\color{MLInk},align=center,inner sep=1.5pt}]
\node[host] (c) {Client};
\node[router,right=2.6cm of c] (r) {Relay};
\node[router,right=3.0cm of r] (s) {Server};

\draw[flowarrow,draw=MLOrange] (c) -- node[ml,above,text width=2.3cm]{broadcast\\ \tiny stops here} (r);
\draw[flowarrow,draw=MLGreen] (r) -- node[ml,above,text width=2.6cm]{unicast to server\\ \tiny + ``I am 192.168.3.1''} (s);

\node[ml,below=0.9cm of r,text width=8.2cm]
 {The server picks the pool matching \textbf{192.168.3.1}, so the client gets an
  address on its \emph{own} subnet --- not the server's.};
\node[below=0.35cm of c,font=\scriptsize\color{MLMuted}]{192.168.3.0/24};
\node[below=0.35cm of s,font=\scriptsize\color{MLMuted}]{different segment};
\end{tikzpicture}
\end{netfigure}

\begin{lstlisting}[style=dcnterminal]
[R1] dhcp enable
[R1] interface GigabitEthernet 0/0/2
[R1-GigabitEthernet0/0/2] ip address 192.168.3.1 24
[R1-GigabitEthernet0/0/2] dhcp select relay
[R1-GigabitEthernet0/0/2] dhcp relay server-ip 10.0.12.1
\end{lstlisting}

\begin{pitfall}
The relay must still be able to reach the server by ordinary routing, and the server needs a \emph{return} route to the client subnet. A relay that is configured correctly but has no return path produces the same silent symptom as no relay at all: the client waits and eventually gives up.
\end{pitfall}

\section{Troubleshooting DHCP}
\begin{netsteps}
\item Confirm the server-side routed interface is up and has the intended subnet address.
\item Confirm \cmd{dhcp enable} is present on the router.
\item For a global pool, verify the pool network/gateway and \cmd{dhcp select global} on the correct interface.
\item For an interface pool, verify \cmd{dhcp select interface} plus any excluded/DNS/lease settings.
\item Confirm the client has DHCP enabled and uses \cmd{ip address dhcp-alloc} on Vlanif1.
\item Cycle the client interface if the exercise requires a new lease, then inspect the client and pool state again.
\end{netsteps}

\end{quickcheck}

\begin{chapterrecap}
DHCP automates address allocation through global or interface pools. Verify both sides: the client has the expected address and the server records the lease.
\end{chapterrecap}
