\section{eNSP workflow}
eNSP provides a visual environment for building and testing IP networks: place devices, connect interfaces, configure them, start the topology, generate traffic, and inspect the result.

\sourceimage[0.90\linewidth]{eNSP main workspace shown in the supplied Lab 2A material}{ensp-home.png}

\section{The topology-building loop}
\begin{netsteps}
\item Drag the required hosts, routers, and switches onto the canvas.
\item Connect the specified interfaces with the correct medium.
\item Configure addresses through host settings or device consoles.
\item Start the devices and wait for them to finish booting.
\item Start Wireshark on the interface to be monitored.
\item Generate traffic, such as \cmd{ping <IP-address>}, and inspect it.
\end{netsteps}

\begin{keyidea}
Use this cycle throughout the course: \textbf{build $\rightarrow$ configure $\rightarrow$ inspect $\rightarrow$ test $\rightarrow$ save}.
\end{keyidea}

\section{Huawei VRP views}
VRP commands are organized into hierarchical views; the prompt identifies the active view.

\begin{tabularx}{\linewidth}{p{0.40\linewidth}X}
\toprule
Prompt pattern & Meaning\\\midrule
\cmd{<Huawei>} & User view; commonly used for display, ping, save, and entry into system view.\\
\cmd{[Huawei]} or \cmd{[R1]} & System view; used for device-wide configuration and entry into protocol/interface views.\\
\cmd{[R1-GigabitEthernet0/0/0]} & Interface view; commands affect the selected interface.\\
\cmd{[R1-ospf-1]} & Protocol/process view; commands affect the selected routing process.\\\bottomrule
\end{tabularx}

\section{Direct-link practice}
R1 and R3 share \cmd{10.0.13.0/24}, using \cmd{10.0.13.1} and \cmd{10.0.13.3}, respectively.

\sourceimage[0.82\linewidth]{Directly connected R1--R3 topology from the supplied Lab 2B slide}{vrp-direct-link-topology.png}

\subsection{Configure R1}
\begin{lstlisting}[style=dcnterminal]
<Huawei> system-view
[Huawei] sysname R1
[R1] interface GigabitEthernet 0/0/0
[R1-GigabitEthernet0/0/0] ip address 10.0.13.1 24
[R1-GigabitEthernet0/0/0] description This interface connects to R3-G0/0/0
\end{lstlisting}

\subsection{Configure R3}
\begin{lstlisting}[style=dcnterminal]
<Huawei> system-view
[Huawei] sysname R3
[R3] interface GigabitEthernet 0/0/0
[R3-GigabitEthernet0/0/0] ip address 10.0.13.3 255.255.255.0
[R3-GigabitEthernet0/0/0] description This interface connects to R1-G0/0/0
\end{lstlisting}

The prefix \cmd{24} and mask \cmd{255.255.255.0} are equivalent.

\section{Verification commands}
\begin{commandmap}
\begin{tabularx}{\linewidth}{>{\ttfamily}p{0.38\linewidth}X}
\toprule
Command & Evidence\\\midrule
 display this & Configuration in the current view.\\
 display interface GigabitEthernet 0/0/0 & Detailed state, address, description, MTU, and counters.\\
 display ip interface brief & Interface addresses and physical/protocol states.\\
 ping 10.0.13.3 & Layer-3 reachability from R1 to R3.\\
 save & Store the current configuration.\\
 display saved-configuration & Stored configuration.\\\bottomrule
\end{tabularx}
\end{commandmap}

\begin{verifybox}
A healthy direct link has compatible addresses and reports both physical and protocol status as \textbf{up}. Verify it with ping, then save the configuration.
\end{verifybox}

\begin{pitfall}
A failed ping is only a symptom. Check interface state first: physical down indicates a link problem; physical up/protocol down points to configuration or peer state. Investigate routing only after the direct link is healthy.
\end{pitfall}
