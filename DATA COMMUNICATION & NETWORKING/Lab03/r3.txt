! ============================================================
! Lab 3 --- R3 static routing (LAN 3 gateway)
!
! This is the router that makes the "one-way routing" lesson land:
! after r1.txt Stage 1, the ECHO REQUEST already reaches LAN 3.
! The ping still fails because THIS router has no way back.
! ============================================================

system-view
sysname R3

interface GigabitEthernet 0/0/1
 ip address 192.168.3.1 24
 undo shutdown
quit

interface GigabitEthernet 0/0/0
 ip address 10.0.23.3 30
 undo shutdown
quit

interface GigabitEthernet 0/0/2
 ip address 10.0.13.3 30
 undo shutdown
quit

! ---------- STOP. Do this experiment before adding routes. ----------
! With r1.txt Stage 1 applied and nothing here:
!   1. Ping PC1 -> PC3. It fails.
!   2. On R3:  display ip routing-table
!      There is no entry for 192.168.1.0/24.
!   3. That is the whole explanation. The request arrived; the reply
!      had nowhere to go. Routing is not symmetric by default ---
!      each direction is a separate decision by a separate table.

! ---------- Stage 1 mirror: primary route back to LAN 1 ----------
ip route-static 192.168.1.0 24 10.0.23.2      ! via R2, matches R1's primary

! ---------- Stage 2 mirror: backup over the direct R1 link ----------
! Same preference value as R1 uses, so both directions fail over
! together. Mismatched preferences give asymmetric routing, where
! traffic leaves by one path and returns by another --- legal, but a
! source of confusing latency and firewall problems.
ip route-static 192.168.1.0 24 10.0.13.1 preference 100

quit
save

! ---------- Verify ----------
! display ip routing-table protocol static
!   Only the preference-60 route is active; the backup is in reserve.
!
! Now repeat the ping from PC1 to PC3. It succeeds --- and it did not
! succeed until BOTH directions had a route.
