\section{Why aggregate Ethernet links?}
The supplied slides introduce link aggregation as a way to treat several physical Ethernet links as one logical connection. LACP automates membership/maintenance of the aggregate, including adding links and responding to recovered or failed member links.

\sourceimage[0.86\linewidth]{Link aggregation between a switch and a server}{lacp-switch-server.png}

\compactsourceimage[0.82\linewidth]{Two physical links presented as one logical link between switches}{lacp-switch-switch.png}

\begin{keyidea}
An Eth-Trunk is the logical bundle. The physical interfaces are members of that bundle. With LACP, the devices exchange protocol information so that the active member set is coordinated rather than being only a local manual configuration.
\end{keyidea}

\section{Prepare the physical interfaces}
The source states that Huawei switch interfaces use auto-negotiation by default. The exercise disables auto-negotiation and forces the two member links to 100 Mbit/s on both switches.
\begin{lstlisting}[style=dcnterminal]
[S1] interface GigabitEthernet 0/0/9
[S1-GigabitEthernet0/0/9] undo negotiation auto
[S1-GigabitEthernet0/0/9] speed 100
[S1] interface GigabitEthernet 0/0/10
[S1-GigabitEthernet0/0/10] undo negotiation auto
[S1-GigabitEthernet0/0/10] speed 100
\end{lstlisting}
S2 is configured the same way. The lab verifies the detailed interface state with \cmd{display interface GigabitEthernet 0/0/9} and the equivalent command for G0/0/10.

\section{Manual link aggregation}
The first aggregation exercise creates Eth-Trunk 1 and adds the two interfaces manually.
\begin{lstlisting}[style=dcnterminal]
[S1] interface Eth-Trunk 1
[S1-Eth-Trunk1] quit
[S1] interface GigabitEthernet 0/0/9
[S1-GigabitEthernet0/0/9] eth-trunk 1
[S1] interface GigabitEthernet 0/0/10
[S1-GigabitEthernet0/0/10] eth-trunk 1
\end{lstlisting}
The same member relationship is configured on S2.

\section{Rebuild the bundle in static LACP mode}
Before changing aggregation mode, the source removes the previous member association using \cmd{undo eth-trunk}. The trunk is then recreated in LACP mode.
\begin{lstlisting}[style=dcnterminal]
[S1] interface Eth-Trunk 1
[S1-Eth-Trunk1] mode lacp
[S1] interface GigabitEthernet 0/0/9
[S1-GigabitEthernet0/0/9] eth-trunk 1
[S1] interface GigabitEthernet 0/0/10
[S1-GigabitEthernet0/0/10] eth-trunk 1
\end{lstlisting}
S2 follows the same configuration sequence.

\section{Manipulate LACP priorities}
The exercise sets S1's system priority to 100 and gives the two member interfaces priority 100.
\begin{lstlisting}[style=dcnterminal]
[S1] lacp priority 100
[S1] interface GigabitEthernet 0/0/9
[S1-GigabitEthernet0/0/9] lacp priority 100
[S1] interface GigabitEthernet 0/0/10
[S1-GigabitEthernet0/0/10] lacp priority 100
\end{lstlisting}

\section{Troubleshooting order}
\begin{netsteps}
\item Confirm the physical interfaces are up and use compatible speed/negotiation settings.
\item Confirm the same member links are assigned to Eth-Trunk 1 on both switches.
\item Confirm both sides use the same aggregation mode.
\item Inspect LACP system/interface priorities if active-link selection is not what the lab expects.
\item Use Eth-Trunk display output rather than checking only individual interfaces.
\end{netsteps}

\begin{pitfall}
A physical link can be up but still fail to participate correctly in the bundle if the Eth-Trunk membership or LACP mode does not match the peer. Treat the logical trunk as a configuration object that must be correct on both ends.
\end{pitfall}
